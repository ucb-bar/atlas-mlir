# Full Smol policy host admission

The full policy has two complete vision images, 16 VLM prefix layers and ten 16-layer expert/Euler updates: 1,421 ordered projection calls and 2,715 physical Atlas launches. `tools/smol_full_plan.py` fixes their geometry, dtype, scale scope and ordering. The 47 complete trajectory references include prefix embeddings/masks/KV, all step inputs/velocities/outputs/timesteps and final full state/actions.

`atlas.full_kernel_assets.v1` is a captured arithmetic preparation, not an executed host. The full builder must preserve the exact original manifest as `host/captured-kernels.json`; the contract binds that member by digest alongside the unchanged replay and trajectory. Selected `kernels.json`, provenance and contract agree on the actual launch programs. Every captured field except source/program paths, requested DMA and selected arena remains identical.

Global program policy is `captured-baseline-v1` or `qualified-reuse-v1`; each launch declares `baseline-v1` or `traffic-reuse-v1`. A baseline is the exact captured program or its audited relocation. A reuse launch must match the public generator's exact source and DMA accounting and the pinned assembler's exact binary. Unallowlisted shapes remain explicitly baseline. Source checks alone cannot admit a different selected binary.

`tools/host_iss/smol_full_contract.py` checks every embedded panel/call descriptor, actual packed weight and instruction byte, complete learned/input/function parameter inventory, writable control state and distinct actual/reference storage. Tables and instruction/weight pointers require read-only file-backed load ranges. The full input conversion buffer holds 3,145,728 BF16 words for the complete 1024-by-3072 vision FC2 predecessor; physical activation panels need at most 786,432 bytes.

The ELF has three host load segments plus a separate zero-file-size arena PT_LOAD. Physical memory extents, BSS, 64 KiB stack and arena must fit the selected end-exclusive DDR range without overlap. Contract/provenance/build placement agree. Full graphs use real host image, attention, normalization, activation, cache, greedy/control and Euler operations; expected trajectory arrays are comparison references and may not replace live successor activations.

The full runner accepts `--workload smol-full` only with an explicit wall budget and a complete admitted bundle. It requires the pinned `9e6313bddecb8ba936206eb347f5cd4e5335282c` model, checks actual host staging/IMEM and every device output/input/guard/DMA/drain boundary, and verifies all final guest buffers. This is a continuous runner interface, not evidence that a continuous full-policy run has occurred. Practical numerical qualification before the deadline requires the separate segmented protocol and its workload-specific harness.

`tools/check_smol_full_bundle.py --bundle BUNDLE --model-root MODEL --out AUDIT.json` performs independent static re-admission using the pinned model's assembler. Use its existing compatible Python environment; it constructs no model Core and executes neither guest nor accelerator code. A passing static receipt is `PASS_STATIC_ONLY`, distinguishes reassembled reuse variants from exact captured baseline relocations, and binds bundle/ELF/contract/source/model bookends.

Physical UART records and FireSim packaging use the shared full-model contracts. QEMU virt's NS16550 transport and the selected board's SiFive transport are explicit different profiles. Native captured-reply C graph tests qualify their stated host components only; they do not establish production raw-adapter, freestanding RV64 helper, guest/model or hardware execution. Any report must state which of those boundaries actually ran.
