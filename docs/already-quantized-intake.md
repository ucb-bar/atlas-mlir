# Already-quantized application intake

The already-quantized path consumes authored E4M3 code tensors and signed int32 exponent tensors. A logical value is `decode_e4m3(code) * 2**exponent`. Codes are stored as unsigned bytes in signless `i8` tensors; they are never interpreted as signed arithmetic operands, decoded into weights, recalibrated, or re-encoded. Exponents remain tensor data, including runtime per-head activation exponents. The source export owns quantization.

Use `atlas_mlir_native.capture.load_export(path)` to register source schemas before loading a saved PyTorch export. Select the authenticated `atlas_fp8` external quantization adapter and call `atlas_mlir_native.capture.normalize_capture` through generic model2MLIR normalization before trace finalization and bundle publication. The target loader preserves original tensor bytes and graph-signature bindings; the generic frontend captures opaque source calls without embedding or transforming buffers.

The target-owned `source_ops` dialect emits typed `atlas.quantize_act`, `atlas.qlinear`, `atlas.qk_matmul`, and `atlas.pv_matmul` operations. Quantization returns codes followed by signed int32 exponents. Contractions consume `(lhs_codes, lhs_exp, rhs_codes, rhs_exp)` with optional qlinear bias. Both matrix operands use logical `[..., rows, K]` orientation; PV receives transposed V codes. The normalizer checks stamped source identities, ordered operand/result ABI, schema literals, immutable buffer inventories, and manifest provenance. `source_translation` implements provider callbacks and immutable contraction intake. Static and dynamic quantizer projections, dequantization, output rescaling and dtype, rhs transposition, scale placement, and bias order remain explicit metadata; normalization executes no dequantization. Unknown semantics, changed cast order, exponents varying over K, incompatible exponent storage, `qconv2d`, float8-to-f32 projection, and nonzero PV `pop_shift` are refused. Packing, arithmetic qualification, and execution require separate target validation.

Select `already_quantized = "atlas-already-quantized-e4m3-signed-exponents-mxu1-model47-v1"` in the source-bound application precision policy. `AtlasApplicationAdapter.source_operation_translators` supplies Merlin's generic typed-source callback registry. Use that registry with `translate_linalg_text`, then the existing `plan`, `compile_region`, `compile_semantic_application`, and publication-verification APIs. The ordinary numerical policies remain separate explicit choices. Capture's `--already-quantized` forbids quantization and numeric dtype rewrites, and the application CLI requires the flag and precision policy to agree.

For immutable model parameters, prefer the existing staged `ApplicationParameters` API. Capture retains the exact exported argument signature and same-conversion trace. Staging promotes only buffers declared read-only by the export's mutation signature. The archive, argument roles, tensor types, offsets, and payload hashes enter source identity. The generated binding verifies the immutable parameter blob before execution. Parameter bytes remain outside generated C initializers and application invocation inputs.

The native contraction uses unchanged FP8 tiles as MXU1 operands. It resets on the first ascending K32 chunk, then continues from the preceding BF16 accumulator. Packing copies logical bytes into A and W rows, pads inactive lanes with positive zero, and preserves transposed views explicitly. The generated readout restores each result with `2**(lhs_exp + rhs_exp)` using the matching scalar, row, or head exponent data. Restoration occurs in the contraction program after its final K32 readout. A numeric predicate selects exact VPU scaling when both per-operand exponents lie in `[-50,47]`, or `[-18,15]` for a fused bounded multiply. The K32 invariant proves every intermediate VPU product remains positive zero or finite normal. Factor broadcasts use the existing physical column and row reductions. Outside the fast range, bounded indexed scalar accesses to initialized VMEM slots perform signed exponent admission and exact BF16 exponent adjustment when the image's fallback budget permits it. The predicate selects a branch; it never selects a DMA address, transfer size, or slot index. Invalid operands or results accumulate a status flag; host C reads that flag before publishing any logical output. Exponent pages copy the original signed int32 bytes, with no numeric conversion. Static and dynamic activation packing use the selected host or device activation_quantizer policy; host preparation remains outside device cycle totals. A float32 contraction output is an exact expansion of the restored BF16 result.

`compile_region` emits one counted device program for each admitted contraction. Batch, M32, N32, and ascending K32 iteration execute in that program. Every K32 step reads out BF16 and reloads that completed BF16 value before continuation, preserving the tile route's arithmetic and rounding boundaries. The old tile route's intermediate non-normal refusal is unreachable for admitted inputs: the [K32 domain proof](already-quantized-k32-domain.md) establishes positive zero or finite normal BF16 with nonzero magnitude in `[2^-26, 2^32]` at every boundary. The proof includes the selected MXU1 integer-anchor arithmetic and its normalization of short sums; it does not substitute an exact dot product. The host packs full unchanged operands and exponent pages once and scatters the final readback; no partial accumulator crosses the host boundary. The selected off-chip I/O window must hold both padded operand blobs and the padded result. Insufficient space is refused rather than split into extra launches. Fixed bases and loop bounds use the existing address, allocation, timing, and drain checks. Constant rematerialization avoids scalar spills obscuring address inductions.

The admitted contraction domain contains positive zero and finite normal E4M3 codes through 448. Negative-zero, subnormal, and reserved FP8 encodings are refused. Runtime exponents outside `[-127, 127]`, summed exponents outside `[-133, 127]`, and restoration that leaves finite normal BF16 are refused. The scalar path checks final raw readouts; the VPU path omits that check because invalid raw readouts are unreachable by the K32 proof. Intermediate K32 accumulators satisfy the same proved finite-normal/positive-zero invariant; the loop has no separate per-step rejection check. The summed scale must materialize as finite nonzero BF16 even for a zero accumulator. Exact subnormal scale factors are admitted by the scalar path while nonzero restored results must remain normal. Per-image execution-budget admission may further narrow this exponent domain: an image without a bounded scalar fallback refuses exponents outside its fast range through the same status-before-publication contract. Bias execution requires a separately checked addition and is currently refused by this native contraction path. These refusals never repair or change source payloads.

The device program checks every paired activation and weight exponent sum before host output publication. Each sum must lie in `[-133, 127]`, so `BF16(2**(lhs_exp + rhs_exp))` is a finite, nonzero, exactly representable BF16 coefficient. The check includes zero accumulators and uses the same scalar, row, and head exponent mappings as readout. On the fast path, the per-operand range proves this sum admission. The Python readout helper enforces the same factor domain.

The counted-image policy retains scalar fallback only for images with at most
two output tiles. Larger images have an explicit zero scalar-fallback budget;
an exponent outside their VPU range sets rejection status. Compilation also
requires the bound reconstructed from the final physical CFG, including K
work and the admitted restoration paths, to fit 1,000,000 instructions. This
can refuse a small image with unusually large K. The policy narrows runtime
admission without changing any admitted result or the runner's default cap.

The optional `already_quantized_mask = "bf16-minfinite-zero-bounded32-nonempty-v1"` admits an unchanged additive mask containing positive zero or the exact BF16 minimum-finite sentinel. It checks finite scores with absolute value at most 32 and nonempty rows, then derives a keep mask. The proof requires that adding any admitted score leaves the sentinel unchanged in float32 and that its exponential underflows to zero. Normalized softmax probabilities are computed before the authored probability quantizer. No packed-exponential renormalization substitutes for that graph.

Select `bf16_pointwise` explicitly when the source needs native BF16 multiplication. Select `source_exp = "f32-to-bf16-bounded32-exp-lut-v1"` separately when the source contains a standalone exponential, including a direct-division SiLU decomposition. This maps one source exponential to the existing bounded BF16 exponential primitive and exact float32 expansion; it preserves the source operation sequence. Source casts, sign-bit negation, and explicitly selected host BF16 addition retain their own checked contracts. Dense requests can also use the [exact source float device routes](exact-float-device.md), with their checked input and publication domains.

I/O and application memory are distinct budgets. Configure `CodegenOptions(io_memory_bytes=...)` consistently for snapshot creation, compilation, export, and verification, and map the same extent in the instruction-model runner. Application capacity excludes the immutable parameter blob and private region scratch. Full models can exceed the default device window and application arena even though individual GEMM tiles use bounded scratch.

Validation separates source byte identity, original-FX arithmetic reference, emitted-program execution, and quality. The portable suites check all BF16 pack encodings, dynamic scale grouping, malformed code and exponent refusal, pointer aliases, source identity, and publication corruption. Independent instruction checks use the selected model revision and RTL numerics. Functional instruction execution does not measure cycles; timing, stream, allocation, and binary-emission verification remain required compiler gates. Hardware qualification and source-framework quality require separate evidence.

Record the producing compiler revision for every executed artifact. A subsequent admission guard creates a new generated host C artifact even when all device-body request digests and program images are identical. Qualify a guard-only change for previously executed data with an explicit source exponent witness, byte-identical device images and parameter payload, and a separate generated-C validation receipt. Keep prior execution and post-run host export identities distinct.

The application region hook admits a connected bounded EXP, add-one, and divide chain as one program when no host region intervenes. The target retains the original operation order and native tile selections, places all stages in a shared checked DRAM arena, and uses the existing virtual-region composer. An exhaustive selected-lane proof covers every admitted bounded-32 EXP input code and proves both removed intermediate encoder guards redundant. The one-valued input is authenticated from its constant/gather provenance and checked again by C. External input guards remain. Layout-changing or unproved boundaries retain their original selected regions; enlargement does not imply universal device closure.

Additional connected alternatives preserve square, seeded reduction, and following pointwise order. An exhaustive BF16 preimage moves the square-result admission guard to an equivalent source-input guard. Device boundary transitions preserve column-zero versus row packing, row broadcasts, signed-zero canonicalization, and operand-specific padding; they accumulate rejection before any logical output is published. Generic pointwise chains keep each original native operation and all external admission guards.

A dense contraction followed only by a bounded pointwise multiplication can use the original multiply as a tile epilogue. Every logical element completes its unchanged ascending K32 sequence, exact exponent restoration, checked multiply-input admission, and original BF16 RNE multiplication, in that order and with original operand order. Independent output tiles retain the contraction's MN order. The multiplication is neither commuted into the contraction nor folded into quantization or exponent restoration. The extra BF16 operand is a separate readonly buffer after the result/status allocation; its page address is the output tile pointer plus a fixed positive offset.
