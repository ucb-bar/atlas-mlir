# Atlas native compiler options

Atlas registers these choices after Merlin's target-neutral `merlin-targetgen native-compile` arguments (`configure_codegen_parser` in [`options.py`](../python/atlas_mlir_native/options.py)); Python callers set the same fields on `atlas_mlir_native.options.CodegenOptions`. Every default reproduces the ordinary lowering. A non-default value enters the options identity record and the application manifest, which partition materialization and tool caches; the tuning key records the fields that affect looped bodies. Pass the same flags to `native-verify`, which rebuilds from its flags rather than reading them from the artifact. C export and counted-publication binding refuse a different options identity as a changed sizing context. Unknown values are argument errors.

Each option selects a candidate, not a resource proof. Native allocation, initialized-read, buffer, address, timing, dynamic-instruction, and image-size checks still decide whether every emitted program is admitted, and no option raises a compiler or hardware limit. The fixed limits are 128 KiB of IMEM (32,768 instructions), the 240 KiB VMEM temporary frame, the selected I/O window, and the execution-instruction budget (1,000,000 per launch by default). Most options fall back to a smaller schedule for shapes they cannot serve and record that decision; the tables list each fallback and refusal. Native compilation errors, failed proofs, and timeouts are never turned into a fallback. Unless a row says otherwise, an option changes transport, placement, or scheduling only: arithmetic, K order, rounding, FP8 codes, exponents, and atomic host publication are unchanged.

## Presets

`--recipe dispatch-reduction` expands `DISPATCH_REDUCTION`: the eleven adjacent patterns marked R below, `batch-panel-cache`, the exponent page cache, `vmem-inputs` staging, the optimized pipeline, static quantizer sizing, exact binary routes, lane groups, binary and cast vector preflight, the device KV quantizer, exact float unrolling, a 128,000,000-instruction execution budget, and a 786,432-byte (768 KiB) I/O window. It is qualified only at that window; at 64 MiB, programs were refused by the spiller work limit (`search_timeout`) and the 30-second tool limit. `--board sophialake` expands `BoardDescription`: DDR geometry, the host reservation (`--host-memory-reserved-bytes`), the staging window, application residency, and `wide-cache`. [Native presets](native-presets.md) describes both, the board memory map, and why their combination is refused. Explicit flags override either expansion in any order, including `--no-` Boolean overrides; a preset name never enters identity.

## Quantized operand reuse

These policies apply only to the already-quantized MXU1 contraction path; there is no MXU0 operand cache. Each output keeps its ascending K32 sequence, BF16 accumulation boundaries, and final exponent restoration. Caches are refreshed for every M row and batch, nothing survives a launch, and VMEM contents never escape as logical output.

| Policy | Schedule | Admission | Otherwise |
| --- | --- | --- | --- |
| `ordered` | The counted schedule. | Always. | None. |
| `row-cache` | Loads each activation tile of a row once into a private FP8 VMEM slot and restores it for every output-column tile; weights stream in groups of four. | At most 64 K32 tiles (64 KiB) and at least two output-column tiles. | `ordered` |
| `prefix-cache` | As `row-cache`; a longer row keeps its first 64 tiles resident and streams the rest through the ordered loop, crossing the boundary with the same BF16 accumulator. | At least two output-column tiles. | `ordered` |
| `wide-cache` | As `prefix-cache` with up to 192 resident tiles (192 KiB). | At least two output-column tiles. | `ordered` |
| `paired-cache` | Pairs of M32 tile rows share each weight-column load, in K panels of up to 64 tiles: two activation rows and one weight column use at most 192 KiB, leaving 48 KiB of the 240 KiB frame. A completed BF16 partial is stored in the output buffer between panels and reloaded as the next seed; the first panel resets. Admits the dense product epilogue. | One batch, an even number of M32 tiles, at least two N32 tiles, and 32 to 192 K32 tiles. | `wide-cache` |
| `panel-cache` | M panels of 2, 4, 8, 16, or 32 tile rows that divide padded M, with K panels of at most 64 tiles inside the same 192 KiB, ranked by weight-read plus partial-result traffic. A batch of independent projections that share one unbatched RHS matrix is traversed as one B×M row range when M is a multiple of 32 and activation exponents are scalar or a contiguous row-page stream. | A candidate that saves traffic. | `wide-cache` |
| `batch-panel-cache` | `panel-cache` inside a counted batch loop, for batched weights and per-batch scales: each batch index selects its own operands, output, and scale pages. Inline final restoration is ranked without a partial-result round trip. | Currently divisible M tile groups, at least two N tiles, one complete K reduction within the 192 KiB panel reservation, and bounded inline restoration. | `wide-cache` |

The 64-tile, 192-tile, and 192 KiB caps are construction limits that bound static code expansion and leave frame space for restoration and ordinary allocation; they are not hardware budgets. For B batches and `(Mc, Nc, Kc)` tiles, `row-cache` reduces activation reads from `B * Mc * Nc * Kc * 1024` to `B * Mc * Kc * 1024` bytes; paired panels reduce weight reads by `Mc/2 * Nc * Kc * 1024` bytes but add `P * Mc * Nc * 2048` bytes each of partial-sum reads and writes for P K panels. These are traffic counts, not cycle predictions.

Panel policies pass a completed tile's final MXU readout directly to restoration when the panel body has at most four M tiles and 512 statically emitted K-tile products; larger bodies keep the counted restoration loop. Multi-guard bodies publish a v2 guard receipt listing every factor loop. Partial sums never cross the C interface: the binding checks the shared status before publishing. Batch panels use one guarded batch counter, whose unsigned range, 32-byte alignment of every interior value, and absence of overflow are proved by both the live SSA analysis and the captured-CFG verifier. The single-status ABI refuses the whole batch after an invalid device exponent; there is no per-request failure isolation.

The execution plan records `operand_reuse_requested`, the selected `operand_reuse`, and its geometry (cached tiles, panel M and K tiles, flattened batch count). Sizing, binding, source verification, and C export replay the recorded policy and rederive the geometry from the source independently of the current options; a malformed or tampered record refuses. Panel sizing retries the older paired policy once on an explicitly retained capacity refusal, and batch panels may retry older policies on proved image or instruction-budget refusals; nothing else is retried. Historical `panel-cache` and `paired-cache` selections keep their ranking and virtual programs for replay.

## Adjacent patterns

The ordered eleven-pattern fusion list in `options.DISPATCH_REDUCTION` is temporary. Its replacement is declared Atlas implementation families, with Merlin selecting the cover.

`--adjacent-patterns` takes a comma-separated subset of the fixed list in `composition_adapter._ADJACENT_PATTERNS`. This is not generic fusion: each name is a recognizer for one specific adjacent operation shape. It offers an enlarged region only when Merlin's ownership proofs (private intermediates, dense identity or proved affine maps, unchanged boundary representations) and Atlas's arithmetic proofs hold; otherwise the original smaller regions remain. Recognizers use no model names, layer numbers, or fixed dimensions. Python callers can wrap `AdjacentDeviceAdapter(base, patterns=...)`; omitting `patterns` there selects every name, while an empty CLI value selects none. Patterns apply in the listed order, so a pattern that consumes another's region must follow it. A larger region is not always faster, because composed boundaries keep their device admission checks.

| Pattern | Region it offers | R |
| --- | --- | --- |
| `adjacent_pointwise` | A connected bounded EXP, add-one, and divide chain as one program in a shared checked DRAM arena; the literal one is authenticated from its provenance. | |
| `adjacent_square_reduce` | A square and trailing seeded reduction; the reduction's input check moves to an equivalent check on the square input under the selected reduction policy. | R |
| `adjacent_reduction_scale` | A square, seeded reduction, checked layout transition, and division. | R |
| `adjacent_pointwise_chain` | Three selected pointwise operations with device boundary transitions (column or row packing, broadcasts, signed-zero canonicalization, padding), optionally ending in a private exact FP32-to-BF16 cast. | R |
| `quantized_epilogue` | An already-quantized contraction and a following dense BF16 multiply, applied per tile after exponent restoration in the original operand order; the extra operand is a separate read-only buffer. | R |
| `quantized_epilogue_narrowing` | `quantized_epilogue` publishing through a private exact f32-to-BF16 cast. | |
| `quantized_narrowing` | A contraction publishing restored BF16 directly through an adjacent exact narrowing cast. | R |
| `pointwise_narrowing` | Selected bounded BF16 multiply, add, subtract, divide, rsqrt, GELU, sigmoid, or closed sigmoid/product SiLU publishing BF16 through a private exact f32-to-BF16 RNE cast. | R |
| `softmax_narrowing` | The selected softmax publishing BF16 probabilities through a private exact cast. | |
| `softmax_input_widening` | The selected softmax consuming original BF16 scores in place of a private exact widening. | |
| `softmax_quantize` | Follows the two softmax patterns: private BF16 probabilities feeding a static activation quantizer are packed to FP8 in the softmax row program. | |
| `pointwise_input_widening` | A pointwise region consuming original BF16 input in place of a private exact widening; encoders that clamp, rescale, flush, or canonicalize zero refuse. | R |
| `pointwise_quantize` | Follows `pointwise_narrowing` and `pointwise_input_widening`: a private BF16 pointwise result feeding a static activation quantizer is packed in its producer's tile loop. | |
| `pointwise_input_layout` | Follows `pointwise_quantize`: a private full-coverage gather, broadcast, reversal, or permutation is absorbed into pointwise input packing. Slices refuse, because checking a whole backing buffer would reject values the original never read. | |
| `expanded_silu` | A closed BF16 widen, sign flip, EXP, add-one, divide, and narrow graph, run as the native five-operation SiLU loop. | R |
| `quantized_operand_permutation` | One private FP8 matrix transpose read during the consumer's tile packing; batch axes must be unchanged and the contraction must fit its counted MXU route. | R |
| `quantizer_input_permutation` | A complete, offset-free private permutation folded into exact activation quantizer input packing. | R |
| `float_input_layout` | A private slice, broadcast, reversal, or permutation folded into the input packing of one exact-float consumer (BF16 add/sub, negation, widening, or narrowing), one mapped input per operation; chains and several independently mapped operands are not yet combined. A private exact add/sub input that repeats a period is loaded once per invocation into at most 96 VMEM tiles. | R |

Every pattern refuses escaping or shared intermediates, changed casts, rounding, or numerical policies, non-dense boundaries, and unbounded maps. The quantize patterns admit static scales only; dynamic scales, shared results, and explicit host quantization keep separate regions. Generated C checks complete input, output, and workspace spans and aliases before device I/O and publishes outputs only after every device status succeeds. No floating-point arithmetic moves to the host.

## Optimized scheduling

`enhanced-virtual-scheduling=true` is an `--atlas-compile` pass option, selected only by `--native-pipeline optimized`; the quantized mandatory pipeline is unscheduled. It makes the virtual scheduler register-aware (prefetch lookahead counts tensor restores, and ready operations that fit the available registers are preferred), gives virtual saves, restores, and slot copies RAW, WAR, and WAW dependencies on their own scratch buffers instead of global barriers, and costs tensor saves and restores as LSU work so independent DMA and MXU work can overlap them. Scalar indexed accesses keep their barriers. Among ready operations with equal earliest start, work needed by the earliest output is preferred, following scratch edges as well as tensor operands. In the spiller, it moves a pure single-use address expression and its single-use scalar operands next to their consumer in the same block, at most once per root per spill pass and within the existing rewrite budget. Dependencies and legality are unchanged; the verifier rejects overlapping assigned scratch slots.

## Shared program bodies

`--compose-atlas-program=share-bodies=true` (Python `compose_regions(..., share_bodies=True)`) is opt-in; the default is straight-line composition. The caller supplies ordered, connected stages with explicit physical buffers; composition does not infer source equivalence or insert boundary conversions. Stages with identical operations, attributes, value uses, DMA lengths, loop bounds, and other constants share one body. Only aligned address literals carried through pointer additions and CFG edges into DMA become parameters; a shape change is not an address change. A counted stage index visits the stages in order and exits through one ECALL. Both the live-IR address analysis and the captured-CFG replay prove every incoming address, so an unaligned choice cannot hide between aligned extremes. `compose_regions` also proves the complete dynamic instruction bound against the selected execution budget before publishing the manifest and records a hashed `instruction-bound.json`; that refusal is independent of whether the image fits IMEM.

Composition treats `atlas.input_dram_bytes` as a member-local frame extent, so a later member's input may be an earlier member's output. `matrix_layout.bf16_matrix_transition` converts complete 32x32-tiled BF16 matrices to dense storage and back on the device, preserving every bit; it refuses tails without a padding contract, overlapping buffers, unknown encodings, and addresses outside the I/O window, and leaves source edge identity, policy agreement, and allocation to the caller. Application compilation selects neither automatically.

## Merlin options that Atlas interprets

| Option | Atlas use |
| --- | --- |
| `--execution-instruction-limit N` | Software budget per launch (default 1,000,000; R 128,000,000), separate from IMEM. It scales exact-float slices, row-softmax row groups (complete rows, equal groups), dynamic quantizer batches (complete groups, at most 256 per launch), and, with static sizing, static quantizer bodies. Every image still needs a proved worst-case bound below it. Softmax plans under the default keep their v1 records; other budgets record `dispatch_instruction_budget` (v2), and replay reconstructs the saved strategy. A simulator watchdog must allow the budget separately, for example `execute_graph.py --max-instructions`. |
| `--io-memory-bytes N` | Device I/O window (default 262,144 bytes at `0x90000000`; R 786,432). Use the same value for the snapshot, compilation, export, verification, and the runner's mapping. |
| `--exact-float-unroll`, `--no-exact-float-unroll` | Off by default (R on). Expands cast and negation inner tiles into fixed-offset slot accesses; widening and negation process two adjacent BF16 values per 32-bit word. |
| `--program-size-limit-bytes N` | A smaller image budget; it cannot exceed the 128 KiB IMEM. |
| `--reduction-unroll auto\|1\|2\|4\|8` | Contraction unrolling; see [instruction memory](instruction-memory.md). |
| `--application-residency`, `--no-application-residency` | Requires a declared physical capacity; the board preset selects it. |

Merlin's own application passes (`--application-buffer-views`, `--application-common-values`, and `--application-compose-reshapes`) are documented in Merlin; pass them to verification as well.
