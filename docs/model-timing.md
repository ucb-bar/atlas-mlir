# Model timing

`builtin`, the default provider, uses handwritten Atlas timing rules. The opt-in `model` provider derives operation timing, resource releases, architecture, operand vocabulary, frontend timing, MXU weight-use windows and curve/DMA costs from the selected [NPU Model](https://github.com/ucb-ee194-tapeout/npu_model) source, data and effective configuration. Reviewed source interpretations derive supported overlap rules; bounded native executions qualify the facts and rules. The standard model CLI selects a winner only among verified emitted candidates scored by native model execution. Compatibility restrictions, compiler adapters, target contracts, numerical gates and optimizer policy remain explicit inputs.

## Regenerate and validate

In the selected model's Python environment, run:

```sh
python -B tools/atlas_model_facts.py --npu-model /path/to/npu_model --out /path/to/new-facts
```

The output directory must be new. This one command derives the supported timing/resource bundle and runs isolated-operation, curve/DMA, weight, overlap, admission and runtime validation. Success publishes `model-timing.json`, `model-overlap.json` and `facts.lock.json`; refusal can leave diagnostics without a lock. No measured overlap catalog or benchmark winner is a derivation input. The command does not derive optimizer policy, ABI placements, numerical/RTL contracts, synthetic target choices, workload expectations or the Python environment.

Generation and native scoring require Python 3.14 and reject other interpreter versions before checking version-sensitive AST fingerprints. The supported contract uses the reviewed ISA/execution-unit classes, 32×32 geometry, register/bank layout and memory map, RTL numerical routines, deterministic initialization and the checked curve-controller semantics. `atlas_derive_*` interpreters check reviewed AST/planner structures and effective `DefaultHardwareConfig` values. `tools/model-timing.lock.json`, capability checks and the operand compatibility snapshot describe parts of this boundary. Unknown structures within these guarded domains or unsupported capabilities refuse; this is a finite supported-model contract, not a proof for arbitrary Python changes.

Before importing model code, generation and native scoring call `atlas_model_semantics.check_model_semantics`. The reviewed `tools/model-semantics.json` inventory independently checks helpers across 17 frontend/storage/ISA modules, including imports, globals, class bases, signatures, decorators and bindings. Coverage includes Core initialization/reset/recovery, `_handle_runtime_error`, IFU/instruction handoff, shared EXU/staged execution, ArchState/sparse storage and ISA dispatch/scalar helpers. Separate existing engine/bank/backend guards cover their dependencies. Scalar-width extraction checks the final store and X0 behavior; capability checks require the supported execution-unit membership/order. Unsupported guarded helpers produce `unsupported semantics: FILE:HELPER`, including suppressing exceptions in Core._handle_runtime_error or changing scalar truncation in ArchState.write_xrf.

The inventory is an authored compatibility boundary, not a whitelist learned by validation. Generated `lineage.semantic_dependencies` records the checked dependencies; `model.source_sha256` binds actual selected source bytes and generator provenance binds the interpreter/inventory. Normalization ignores comments, locations and leading docstrings, and permits limited local renames and adjacent method reordering in reviewed simple scopes/classes. Arguments, executable statements, external bindings and unsafe order changes remain checked; existing VPU guards still conservatively refuse renaming a VPU local variable or reordering its methods. Python/PyTorch behavior, effective configuration interpretation and selected numerical routines remain external boundaries with source/data identity and numerical validation.

`runtime-validation.json` records five positive/negative full-Core pairs: VPU issue-busy, VMEM and MRF conflicts, invalid VPU pair operands and branch-delay-slot control flow. Positive controls must drain to ECALL; negative controls must propagate specified native exceptions with the fatal-error flag unchanged. Operands, drain slack and the 512-cycle bound are hand-chosen validation coverage. Production requires this report before publishing the lock; these controls qualify the reviewed fatal-error contract without proving every possible runtime fault.

The derived payload also binds `engine_admission` and `dma_admission`, excluding their validation receipts and producer identities. Their predicates are extracted from reviewed model source/configuration before native validation; measurements never choose admission gaps. Validation sample coverage is a versioned policy. A passing gate is required before the one-command flow publishes its lock.

A bounded Core gate checks phase order, ordinary/DELAY issue edges and DMA.WAIT visibility after flag clear. Its shorter-edge prediction checks compare observed traces rather than execute additional rejecting native runs. Operation probes come from `IsaSpec`; validation checks zero/nonzero inputs, instrumentation on/off, control traces, progress, drain, event ages and releases. Curve validation compares an independent fact interpreter with native backend streams and isolated/mixed DMA, including backpressure, translation and scaling. The driver checks source, numerical data and derivation/observer tools remain unchanged during generation. Native observations validate derived timing rather than supply it.

Production requires `atlas.derived_facts.v1`, with successful validation bound to deterministic semantic inputs, vocabulary, complete releases and MXU weight-use windows. The payload binds overlap rules through canonical `overlap_rules_sha256` over `{schema, age_convention, contract, source_contract, pairs, composition}`, excluding `producer_sources` from `source_contract`. The compiler independently hashes those semantic fields from the overlap artifact and checks the binding. Raw observations and isolated synthetic fixtures remain restricted to test/validation APIs.

The lock records selected file and semantic digests; elapsed times belong in `timing-receipt.json`, outside semantic identity. Preserve manifests, frozen candidates, sample descriptors and native reports for reproducibility. Hashes and internal records provide integrity and traceability: compilation neither reruns derivation nor authenticates an external author's claimed execution.

## Source facts and explicit assumptions

Architecture extraction combines configuration with allocation/banking implementation: VMEM capacity/banks; MREG geometry/count; weight/scalar/exponent/CSR capacities; DMA channels/beat/transfer/in-flight limits; DRAM range; fetch width; and bus/link geometry. `BankConflictChecker` supplies bank/row mapping and logical-register guards; BF16 helpers supply pair layout; `ArchState.write_xrf` supplies scalar width. Consumers check the supported layout, including 32 physical MREG banks, 32 rows, 1024-byte registers and six 262144-byte VMEM banks. Extraction followed by a capability check does not imply arbitrary-layout support.

Operand vocabulary comes from ISA operand types/roles and VPU/MXU planners, including directions, counts/offsets, row passes and accumulator/weight/exponent accesses. ISA metadata must match the compiler compatibility snapshot. Compiler adapters retain encoding/query syntax, names and token/resource translations; exponent sampling remains at issue. After reviewing an adapter change, regenerate the snapshot with `python -B tools/atlas_derive_vocabulary.py --npu-model /path/to/npu_model --output tools/model-timing-vocabulary.json`, then regenerate facts.

Frontend extraction checks Core/scalar execution, IFU/architecture redirect ordering and scalar ISA implementations. It derives ordinary issue timing, scalar accesses, branch/JAL delay slots and DELAY semantics. The reviewed model gives `1 + (imm & 0xFFF)`; scheduling currently accepts ordinary/base gap one and that 12-bit mask, refusing other values until adapters support them.

Curve facts carry unloaded latency, every read/write mix's response pacing, queue/history limits, channel/frequency scaling, DMA startup/request intervals and rounding/reset behavior. The supported controller uses unloaded latency, converge=1 and peak pacing. Backend queue capacity is distinct from engine in-flight capacity. Canonical configuration, source and selected curve bytes bind compilation/scoring; hashed dormant overrides do not drive the active backend.

The one-cycle `scratchpad_read_latency` in `scratchpad_assumptions()` is inactive production compatibility metadata, not derived timing. Complete derived reservation releases override its legacy test-only fallback; production rejects missing releases. VPU `_read`, MXU `_sample`, LSU and XLU synchronously sample tensors on request edges; no independent SRAM response event exists. DMA store staging uses `cycle + 2`, without separating SRAM response from queue staging. Extraction checks these pipelines and derives aggregate staging, but cannot derive standalone SRAM latency. `scratchpad_contract.limitation` labels the inactive field explicitly; observer comparisons exclude it.

## DMA admission and proposals

DMA admission is asynchronous: Core can issue a transfer on a free channel at the ordinary frontend gap while independent compute or other channels remain live. Loads and stores share registered DMA request/response paths; curve history, queue backpressure and VMEM grants determine progress after issue. These source-derived admission semantics have no state-independent completion age. The compiler therefore retains completion-scoped VMEM ownership, matching waits, channel-reuse checks and the independent RTL ring rule. DMA/LSU conflicts cannot be discharged by an isolated DMA estimate. The conditional service bound remains a proposal cost only.

The shared DMA source, phase, startup and geometry contract is owned by `atlas_derive_curve.py` and exported in `dma_timing`. Admission consumes and cross-checks that record; its channel, grant, alias and wait obligations remain explicit. The nested `proposal_contract` belongs to the same derived-facts semantic payload. The one-command flow extracts Core/DMA phase order and checks the source premises for backend pacing, registered engine occupancy, source-ID reuse and retirement. S1 checks the channel before DMA processes a response and clears its flag: retirement is visible to a nonstalling wait on the following edge. Positive backend latency separates the final request from the final response, so the registered dispatched bit permits retirement on that final-response edge. Native Core tests validate the exact visibility boundary and its one-short stall; they do not choose the offset.

The compiler no longer simulates a hand-written cold endpoint recurrence. It uses a checked analytic service envelope over **every** converted curve row, covering arbitrary retained read/write history. Let `M` be the maximum of unloaded latencies, curve spacings and minimum latency, and `I` the extracted issue interval. The source-derived bound quantum is `ceil(M) + I`; the isolated retirement-age bound is `startup[direction] + beats * quantum`. The exported contract records source expressions, proof premises and scope, and the compiler recomputes the quantum from the curve operands. This conservative bound is a proposal input, not a fitted duration or an exact native completion prediction.

The bound assumes an initially drained engine/backend, no denied VMEM grants and cycle/arithmetic operands within the compiler’s signed 32-bit cycle domain. The ceiling does not subtract the model rounding epsilon: that subtraction is unsafe at floating-point boundaries even at small cycle counts. Native mixed-stream tests exercise history, live occupancy and grant behavior separately; they do not turn those excluded conditions into an unconditional completion guarantee. Arbitrarily long grant denial has no finite source-only completion bound. The versioned `compiler_policy` serializes command proposals after the preceding proposal retirement plus one cycle; actual model commands can overlap. Both physical critical height and wait placement call the same provider proposal interpreter. Model timing never discharges a DMA wait, and the ring/register/port/VMEM checks are unchanged.

Curve/configuration operands, edge visibility and the conditional analytic envelope derive from the selected model; its shipped curve data may be empirical. Drained/no-denial preconditions, capability guards and finite validation coverage are authored scope choices. Native traces and scores validate or rank; they never supply timing facts. Builtin retains its separate handwritten DMA policy for schedule identity.

## Source-derived overlap

`atlas_derive_overlap.py` and `atlas_overlap_rules.py` interpret reviewed source predicates, isolated event ages and deferred releases to compute suffix-safe pair gaps and composition classes. Native runs validate frozen rules rather than fit minima. Supported configuration changes regenerate matching rules; production does not silently fall back to isolated-only scheduling.

Structural checks extract MXU compute tracker depths and VPU slot capacity from source. This model revision has no configuration fields for these capacities: MXU `inflight_depth` class literals and the matching VPU `len(live)` predicate/contiguous slot tuple are the supported parameters. Reviewed AST normalization permits MXU depths 1..64 and VPU slots 1..3; those bounds are compiler qualification limits, not timing facts. Changed parameters regenerate pair bounds, composition capacity and native saturation controls. The consumer reads the generated capacities. Geometry remains 32×32 with 64 logical MREGs and 32-cycle MXU sequencers: model constructors, row planners and physical banking contain fixed structure, so changing these still refuses with an unsupported-source/geometry diagnostic.

VPU issue liveness and retirement use the guarded native operation's `write_last` field, selected latency minus one; engine metadata retains this endpoint under the existing `final_write_age` key. Physical row writes may finish earlier. For example, changing row-sum latency from 39 to 40 leaves its last row write at age 38 while keeping the operation live until age 39. Admission derives this endpoint from the inert source issue plan, requires every row write to fit within it, and uses the same endpoint as the authoritative overlap rules; the last observed or derived row-write event cannot shorten it.

Scalar LSU admission uses the extracted load-response spacing; stores and scalar/vector combinations are constrained by their actual bank, register and writeback obligations. VPU commands can coalesce reads of the same logical register and row on one edge, as the native read cache does; other engines and uncertain intervals across waits cannot use that exception. Unsupported internal operand layouts remain explicit compiler capability limits.

Coverage includes complete legal MXU and VPU cross-command register/bank equivalence relations, VPU/XLU pairs in both directions, and immutable aligned scalar LW/SW contexts. VPU operand legality follows the guarded ISA roles, even-pair alignment, exact same-register/row read-cache coalescing and physical port predicates. Restricted-growth partitions enumerate bank-pair identities, logical halves and singleton parity; they include duplicate sources, in-place operands and simultaneous aliases across commands. Static checks prove every legal internal class reads each input row before overwriting it; native standalone execution is compared with direct ISA execution for every class. Simulation validates these source-selected domains and never fits their gaps.

XLU shares logical MREG reservations and physical ports with VPU, but has no VPU read cache. Source-derived disjoint pairs allow gap 1 in either direction; an observed gap 33 is not used as a timing input. Aliased operands use exact source request ages and deferred releases. Mixed-unit chains remain conservative, as do unknown relations.

The bounded native gate uses versioned policy `source-mechanism-boundaries-v2`: complete standalone VPU/XLU internal alias checks against the ISA, followed by operation/mechanism boundary samples independent of benchmarks. Pair checks cover minima and later suffix points, one-short controls, zero/nonzero operands, exact issue ages, complete drain and serial-reference final state; mixed pairs tick both native units against one shared checker. Chains exercise slot/tracker limits where they can bind, nonadjacent aliases and retired-prefix port history. Zero-gap controls are encoding rejections. A passing one-short control records conservatism without changing the derived minimum. Enumeration, coverage bounds and data patterns are validation policy; native outcomes are measurements, while source predicates/configuration supply the admission facts. All regenerate through the command above.

The VPU/XLU pair and composition rules are the sole overlap admission authority; engine metadata cannot bypass them. Admission requires the exact relation/gap; larger live sets require every live pair, supported composition and dynamic capacity. Port/register holds, retired history, weight/accumulator ownership, alias proofs and epoch boundaries remain enforced. Waits invalidate earlier eligibility. DMA history/grants/backpressure exclude it from fixed overlap windows. Bounded samples do not prove arbitrary operand/data cases, mixed chains or RTL equivalence.

## MXU weight-use lifetime

`mxu_weight_timing` (`atlas.mxu_weight_timing.v1`) derives weight masks from `hardware/mxu.py:_MatrixExecutionUnit._weight_uses`, checking row/column mapping, sampling and push-write edge order. The inner engine reads every weight at ages 1 through 32. Systolic PE(i,j) reads at ages `1+i+j` through `32+i+j`; weight-buffer row i is the output-column axis. A push replaces a whole row, so that row's union spans `1+i` through `63+i`. Facts carry the affine PE window and all 32 projected row windows per engine in the semantic payload. Unsupported mappings/masks/order stop derivation; missing or inconsistent windows stop production loading.

The provider uses each row's first/last use instead of the former age-zero-to-busy-end envelope. Ordered-resource dependencies derive push-to-matmul/matmul-to-push gaps of 1/63 for MXU0 and 32/32 for MXU1 with the pinned model's row writes at ages 1 through 32. Strict dependency order and issue predicates remain enforced even though sampling precedes writes on an edge. Both matmul modes and both slots use these windows; another slot creates no weight data dependency.

Weight dependencies come directly from ordered-resource accesses, independently of overlap admission. Precise windows do not by themselves admit concurrent engine/resource use: occupancy, MREG ports/releases, slots, complete overlap epochs and capacities still apply. Fresh generation validates each PE's first/last use, boundary mutations and native streamed push boundaries with rejecting one-cycle-early controls. These observations challenge derived windows without supplying them.

## Compile and select

```sh
python -B tools/lower_atlas_program.py input.mlir \
  --output-dir selected --atlas-bin-dir build/bin \
  --provider model --npu-model /path/to/npu_model \
  --model-facts /path/to/new-facts
```

The loader reads fixed filenames and locked digests; separate pair/composed files are unnecessary. Omit `--model-facts` to regenerate automatically. The compiler pass accepts `--select-atlas-model-evidence="facts=/path/to/new-facts"`. Repeated `--model-region FILE` options supply disjoint DRAM regions with `address`, `initial_hex` and optional `expected_hex`. Outputs must be empty; path checks reject traversal, symlink ancestry and prohibited names before traversal.

Derived costs guide scheduling, allocation, delay slots, waits and lowering. The projected-Core replay carries checked Core edge facts and a common transition program interpreted by Python and C++. Its dependency waits, serial virtual engines, anonymous DMA channels and drained-transfer serialization are compiler proposal policy. Core itself does not stall automatically on graph dependencies or engine conflicts. A virtual graph omits emitted setup, branches, allocation, ports, exact waits and mixed memory history, so this replay is not a full Core simulation. Selection receipts report prediction errors against native candidate scores; those measurements do not change timing facts or establish completion.

In the standard CLI, every selectable emitted candidate passes compiler verification and native model scoring. Scores cover first issue through drained ECALL, and winning emitted words are the scored words. Identity mismatches, propagated native faults, incomplete drain and supplied expected-output mismatches fail selection. The pre-import guard and native controls qualify the supported runtime-error behavior; a false flag alone would not establish it. Expected-output checking covers supplied regions rather than universal numerical correctness. Library test hooks may inject scorers and are not the production selection contract.

DMA completion requires matching waits. The eight-slot command ring, `kAtlasDMACommandSlots`, is a separate RTL contract absent from model-derived architecture; the model does not enforce it. Launch n reuses n−8's slot, so the compiler moves a pending n−8 wait before n and rejects pending-slot overwrite. Builtin retains its existing behavior.

The versioned `tools/model-search-policy.json` defines compiler search policy separately from source timing: budgets, seeds, ordered candidate/rank pools, ranking, wait/PACK alternatives, objectives, tie order and engineering bounds. Python consumes the definition; CMake generates the compiler constants and policy identity. Selection receipts bind its canonical hash and effective invocation overrides, and check the compiler policy identity. Algorithm names identify reviewed implementations rather than claiming arbitrary algorithms are configurable. The facts bundle binds only the projection subset needed to reproduce its proposal semantics; budgets and seeds do not affect its semantic digest. The producer manifest still binds the complete policy file as provenance. Policy is reproducible from the compiler checkout; it is not extracted from the NPU Model.

The same definition fixes the supported execution contract to RTL numerics, deterministic initialization and fatal runtime errors; unsupported changes refuse. It names the reviewed finite validation suite, whose revision, scope and limits are recorded in the validation report. The final suite-validation.json binds the completed operation, weight, runtime, replay, DMA, engine-admission and overlap gates after they all succeed; the lock records its digest. Individual validator case constants remain in the versioned implementations except explicit Core-edge controls. This is reproducible validation policy, not exhaustive operand, arbitrary-program or RTL-equivalence proof.

Default `full` search bounds initial/order/group attempts at 32/96/204, using deterministic batches of 12 and groups up to four nodes; `selection` allows 24 initial attempts without order search/PACK alternatives. Refused attempts consume budget. Native scoring chooses winners. `--guarded-pack` rewrites eligible PACKs to MXU operations. Remaining PACK scale codes are restricted to observed E8M0 codes 122..128: an empirical numerical target gate, not derived timing or universal numerical proof.

Representative proposal probes use selected ISA operand roles, capacities and source-derived register spans. Checked source planners establish operand-independent isolated event ages; a same-unit interval belongs only to the selected representative relation. This is not a proof that arbitrary aliases or banks have that interval. Actual scheduling still checks exact footprints, dependencies, reservations and supported overlap relations. Scalar load-plus-store composition and conservative address materialization describe compiler lowering templates; they do not add model timing facts.

PACK proposal dimensions use derived register rows, bytes, scalar-word width and BF16 spans. Individual instruction costs and branch/delay-slot spacing use operation/frontend facts. The compiler's interleaving template, omitted setup and presumed useful filler remain explicit proposal policy; deriving their dimensions does not prove the entire estimate exact. Conservative block drains and wait-uncertainty invalidation are compiler policy, while the edge spacing used to implement them comes from the frontend contract.

PACK reload/preload applicability and loop wait/address proofs are compiler safety obligations. Reload motion requires the same block, the final trailing reload, no intervening label and an independent pending weight. Preload requires an adjacent matching matmul and a weight register disjoint from the PACK source pair and output. Scalar overlap requires proving aligned immutable addresses for every iteration of the supported loop. These checks are not timing measurements, and a favorable proposal cost never bypasses them.

## Scoring targets and invocation identity

Default `curve` uses the checked model's curve backend. `fifo43` selects `standalone-atlascore-fifo43` from `tools/model-scoring-targets.json`: latency 43, one cycle/beat, acceptance on absolute backend cycles 0–3 of each 11. This explicitly synthetic harness target is neither model-default nor extracted RTL timing. A versioned adapter maps its periodic descriptor to the model's `accept_fn` hook.

`selection.json` records the selected native profile's effective configuration, source/numerical/base identity, synthetic provenance and canonical SHA-256 excluding `sha256` itself. Callback receipts contain the adapter/descriptor; curve receipts contain checked curve data. Workers share an invocation snapshot. Default curve selection minimizes only selected-model curve cycles; exact ties retain the earliest canonical candidate index, assigned before parallel execution. This non-timing rule also governs search parents, restarts and patience. `--profile fifo43` explicitly opts into the synthetic target as the sole timing objective, with the same index tie rule; default curve selection never scores FIFO43.

The hashed `objective` receipt identifies `selected-profile-cycles-then-index-v1`, the profile, scoring kind, comparison fields and `canonical-candidate-index-v1` tie rule, linked to the effective scoring-configuration hash. Its SHA-256 covers sorted-key compact JSON excluding `sha256` itself. Builtin compilation and injected library scorers are labeled separately. The objective and tie labels come from the same `model-search-policy.json` definition bound by `search_policy` and run provenance; unsupported secondary objectives refuse. These rules are versioned search policy, not model timing facts; facts regeneration does not derive them.

The scorer snapshots supplied region contents and named target descriptors for worker use. Workers independently import the model and compare selected configuration with provider evidence; curve scoring binds checked bytes. The run receipt and completion checks below cover persistent input changes beyond these cached worker identities. Keep model/tool/data/environment inputs fixed throughout a run.

Production model selection also records `provenance` (`atlas.run_provenance.v1`). Its `semantic_sha256` covers the source program, ordered region addresses and exact decoded initial/expected bytes, model source and numerical manifests, effective configuration and curve content, derived facts, compiler sources and executable bytes, tool/profile-adapter sources, Python/Torch/NumPy versions, invocation settings and used scoring profiles. Exact supplied region JSON and decoded bytes are archived by content hash in `provenance/objects/`; absent expected bytes mean no numerical-output oracle. Empty regions retain the existing cold deterministic reset scenario. Injected library scorers are test hooks and do not receive a production provenance claim.

`provenance.evidence` holds absolute locations, Git revision labels (null for source-only copies), exact facts/lock/report-bearing artifact hashes and original profile receipts. These are distinct from semantic input identity: moving unchanged inputs and executables between checkouts preserves the semantic digest; changing an executable is a different tool input even if its source revision is unchanged. The selected curve pathname is represented semantically by its bytes, including inside derived configuration; `provider_facts_sha256` retains the original sealed provider digest separately. Git labels do not substitute for content hashes or establish that a binary was built from a particular checkout. Reports and elapsed times neither define timing nor influence ranking.

Selection captures input files before preparation, including external curve data, and rehashes file bytes and model/tool rosters after all scoring workers exit, before copying the winner or publishing a successful receipt. Persistent changes, removals, additions and unsafe paths refuse publication. Conservative roster checks reject every symlink under the model source/data and compiler lib/include/tools trees, including unused files or ignored suffixes; input paths also reject symlink ancestry. These checks apply to model selection; builtin retains normal resolved paths. This is a completion check, not an immutable filesystem or an authentication mechanism: transient changes restored before completion and changes after publication require an externally immutable environment to exclude. Dependency versions identify the numerical runtime; they are not a full operating-system/container snapshot.

The single `provenance.semantic.search_policy` field contains the versioned policy receipt and effective invocation settings from `atlas_search_policy`, identical to the selection receipt's policy field. There is no selector-hash fallback or second policy definition. The one-command facts flow regenerates derived model inputs and reproduces explicit proposal policy; rerunning selection reproduces workload receipts and native scores. Workload oracles, package versions, synthetic targets and optimizer choices remain supplied inputs.

## Updating for NPU Model changes

For supported changes such as DMA frequency, backend queue/history/channel scaling, engine in-flight capacity, selected curve data or recognized latency expressions, regenerate into a new directory and compile/score against that checkout and bundle. Operations, curve costs, weight windows and overlap regenerate/revalidate together. An unchanged score can be a valid result; dormant backend fields cannot change active timing. Unsupported geometry, tracker/slot/sequencer structures, ISA changes or unrecognized helper semantics require reviewed extractor/consumer updates rather than pin changes. Some benign refactors are accepted by normalization; others conservatively refuse.

Rerun relevant compiler/evidence tests, representative searches, numerical gates and DMA ring checks; preserve program/input/source/configuration identities and regressions. Historical results alone do not qualify an integrated bundle. Search bounds and conservative policy do not prove optimality or physical timing. Curve bandwidth lacks address sensitivity, so close model rankings can reverse on a SoC; validate the intended target.
