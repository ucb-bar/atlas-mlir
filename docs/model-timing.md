# Model timing

atlas-mlir has two timing providers. `builtin`, the default, uses Atlas's handwritten timing rules. The opt-in `model` provider uses isolated operation timings, reservation releases and curve/DMA scalar costs derived from the [NPU Model](https://github.com/ucb-ee194-tapeout/npu_model), then selects schedules by executing verified candidates on that model. Overlap admissions use a supplied simulation-measured catalog plus handwritten structural rules. Architecture and operand vocabulary are derived from the selected model and checked against compiler capabilities; frontend timing is derived from the model core, while conservative compiler policies remain handwritten; this is not a fully source-derived timing environment.

## Derive and validate facts

Derivation is an explicit step. Run it in the selected NPU Model's Python environment, using a new output directory:

```sh
python -B tools/atlas_model_facts.py --npu-model /path/to/npu_model --out /path/to/new-facts
```

`tools/atlas_model_facts.py` derives issue/completion windows, reservation releases, architecture and operand vocabulary from model source and the selected `DefaultHardwareConfig`, using the `atlas_derive_*` modules. Reviewed timing source shapes are recorded in `tools/model-timing.lock.json`; architecture and vocabulary extraction also enforce AST/planner contracts. The frontend and scratchpad extractors check their reviewed source structures. Unsupported structures stop derivation. The reviewed AST contracts use Python 3.14. Compilation checks named lowering/semantic capabilities instead of requiring the default configuration identity: fixed 32×32 tile/register/bank layout and memory map, supported ISA and execution-unit classes, RTL numerics, deterministic initialization, fatal runtime errors and the reviewed curve controller. This does not enable arbitrary geometry.

Curve frequency, queue depth, history window, channel scaling, minimum latency, selected curve bytes and DMA in-flight capacity flow through derived facts. Canonical configuration (including floating-point values), source and curve hashes bind derivation, compilation and native scoring to the same settings. Legacy fixed-backend latency/beat overrides and unused bus/link estimates remain hashed but do not drive the selected curve backend. Queue capacity and engine in-flight capacity are independent.

The operation probes come from `IsaSpec`. Source-derived facts are checked against independent isolated executions with zero/nonzero inputs and instrumentation on/off. Control traces, progress, drain, event ages and releases must agree, and runtime errors remain fatal. The driver also verifies that model source, numerical data and derivation/observer tools stay unchanged during the run. Only successful validation produces the final `model-timing.json` and `facts.lock.json`; intermediate diagnostic files can remain after a failed validation.

Curve facts include unloaded latency, response pacing for every read/write mix, queue capacity, issue-history window, channel/frequency scaling, DMA startup, request interval and rounding/reset semantics. The supported controller uses unloaded latency with converge=1 and peak pacing. `atlas_validate_curve.py` compares an independent fact interpreter with native backend streams and isolated/mixed DMA runs, including backpressure, translation and scaling. These checks validate proposal costs; they do not establish completion of an arbitrary compiled stream.

Pass `model-timing.json` and its `op_timing_sha256` from `facts.lock.json` explicitly when compiling. Compilation does not derive facts or manage a facts cache. Production selection requires `atlas.derived_facts.v1`: source derivation and successful validation records bound to a deterministic semantic payload, the vocabulary digest, and complete reservation release coverage for every supplied operation. The compiler hashes the carried payload serialization and compares its decoded contents with the actual model identity, configuration, architecture, operand vocabulary, ISA metadata, operation/release, DMA, frontend and scratchpad inputs. DMA validation must bind that same payload; a self-reported successful report hash alone is insufficient. Raw observations and explicitly marked test fixtures are accepted only by validation or test APIs, never by production provider selection.

`facts.lock.json` records both the selected file digest and `semantic_payload_sha256`. Elapsed derivation and validation times live only in `timing-receipt.json`; they cannot change the facts, semantic payload, or validation-report digests. Producer/observer manifests and validation-report identities remain receipts outside the semantic payload. This is an integrity and provenance contract, not a signature: the compiler does not independently authenticate an external author or reexecute derivation. Generate artifacts with the explicit command above and retain their receipts.

Frontend timing comes from `hardware/core.py` (`Core.tick`, `_tick_s1`), `hardware/exu.py` (`ScalarExecutionUnit.tick`), the fetch/redirect ordering in `hardware/ifu.py` and `hardware/arch_state.py`, and scalar `exec` methods in `configs/isa_definition.py`. Structure checks establish one ordinary issue edge, same-edge scalar register accesses, the single branch/JAL delay slot and control handling. The DELAY mask is extracted from the Core assignment, giving `1 + (imm & 0xFFF)` on the pinned model. The provider consumes these values and source-derived operand accesses; mapping compiler instruction fields to model operand names remains a separate encoding adapter. The compiler's existing delay synthesis and branch-slot scheduling support ordinary/base gap one and a 12-bit DELAY mask; other extracted values receive a precise capability refusal until that adapter supports them.

Scratchpad response latency is an explicit target assumption, defined once by `scratchpad_assumptions()` in `atlas_derive_scratchpad.py`. The pinned model does not expose an independent response event: VPU `_read`, MXU `_sample`, LSU and XLU sample tensors synchronously on request edges. DMA `DmaExecutionUnit.tick` stages stores with `cycle + 2`, but executable source does not separate SRAM response latency from queue staging. The extractor checks these source structures and extracts the aggregate DMA staging interval; it cannot derive a standalone SRAM response latency of one. The facts label this limitation in `scratchpad_contract`, and observer validation excludes the assumed field from measured comparisons. Model changes to these pipelines require renewed review rather than silently treating the assumption as observed evidence.

## Architecture and vocabulary provenance

`architecture` is generated from the effective `ArchStateConfig` and default hardware configuration: VMEM capacity, bank bytes/count, MREG count/rows/row bytes/register bytes, weight-buffer and scalar/exponent/CSR capacities, DMA channels/beat/transfer/in-flight limits, DRAM address range, fetch width and bus/link geometry. `bank_conflict.py:BankConflictChecker.access_mreg` supplies the physical bank modulus and row mapping; its reservation guard supplies the logical register limit. BF16 pair count/stride and tile bytes come from the bank-conflict pair helper and `ArchState.read_mrf_bf16_tile`/`write_mrf_bf16_tile`; scalar word width comes from `ArchState.write_xrf`. Extraction checks the allocation and VMEM banking implementation against those configuration fields.

Existing facts need regeneration to supply this metadata. The model provider requires these facts and checks them against `AtlasTarget.h`/`AtlasTiming.h` capabilities and the explicit configuration. This also guards fixed layout assumptions in the separately maintained overlap consumers (32 MREG banks, 32 rows, 1024-byte registers, six 262144-byte VMEM banks). Those consumers are not generalized to arbitrary geometry by this change. Builtin keeps the same constants and behavior. DMA command-ring depth is intentionally absent from `architecture`: `kAtlasDMACommandSlots` is an explicit RTL contract that the model cannot derive.

`operand_vocabulary` is generated from `configs/isa_definition.py` operand types/roles and the VPU/MXU unit planners. The derived metadata determines read/write direction, MREG register counts, offsets and row-pass counts, and MXU accumulator/weight/exponent resources. `isa_metadata` records model operand types, named roles, accesses, execution units and compiler syntax tokens. The compiler compares generated vocabulary with its compiled snapshot and checks all supported metadata operand signatures and engines against its instruction table. The checked-in JSON is a generated compatibility snapshot, not an independent source of model operand semantics; fresh derivation refuses a mismatch before simulation.

Compiler-authored adapters retain serialization/query syntax, timing-block and C++ class names, operand/token and resource-label translations, event-group names and conditional second-source markers. Model types, roles, dispatch and planner accesses determine their applicability. Exponent reads retain issue-time sampling; matmul weight reads retain the conservative lifetime policy. Representative operand numbers are extraction probes, not hardware constants.

Regenerate the compatibility snapshot after reviewing an intentional adapter change with `python -B tools/atlas_derive_vocabulary.py --npu-model /path/to/npu_model --output tools/model-timing-vocabulary.json`, then run the normal facts command. The normal command always rederives and checks the snapshot before validation; stale operand semantics cannot silently override the selected model.

## Overlap evidence

Isolated operation facts do not admit overlap. At this stage, pair, chain and composed evidence remains the supplied experimental simulation-measured catalog pinned to model revision `9e6313bddecb8ba936206eb347f5cd4e5335282c` and its locked configuration; it is not derived from source. Separate evidence covers exact ordered pairs, complete chains and bounded composed classes, with passing gaps and rejecting controls including the exact one-short gap. `tools/atlas_model_pairs.py` projects confirmed pairs from a sealed master and its validation receipt. `atlas_model_composition.py`, `atlas_model_chain_composition.py` and `atlas_model_composed_projection.py` replay and project composed evidence; `lib/AtlasModelPairs.cpp` checks it.

Evidence remains bound to the exact facts-file SHA-256. With unchanged model, configuration and producer/observer code, fresh derivations now reproduce both that digest and the semantic payload digest, so the same pair/chain/composed evidence binds without re-projection. Elapsed times are separate receipts. Migration from older facts or changes to producer receipts can still change the file identity; existing catalog admissions may be transferred only after proving the covered model/configuration and timing semantics unchanged and updating the dependent evidence bindings. This does not generate a new measured catalog. On another model revision or configuration, overlap evidence is unavailable: compile without `--pairs` and `--composed`, using isolated lifetimes. Non-default configuration or curve identity disables default-pinned overlap evidence at selection with a warning and isolated-lifetime fallback; incomplete option pairs still reject. Published overlap-enabled results do not transfer to that fallback. Pair admission requires the covered operation/relation and gap. Larger live sets require complete chain or admitted composed coverage, all live pairs and structural capacity. Handwritten capacity, port-window, shared-engine, weight/accumulator and alias rules further constrain admission; matching the supplied measurements validates those rules without deriving them. Register, port, VMEM and DMA obligations remain enforced; waits invalidate earlier overlap eligibility. Scalar PACK overlap additionally requires the covered immutable aligned LW/SW address proofs. Without overlap evidence the compiler uses isolated resource lifetimes.

## Compile and select schedules

The lowering driver runs candidate selection:

```sh
python -B tools/lower_atlas_program.py input.mlir \
  --output-dir selected --atlas-bin-dir build/bin \
  --provider model --npu-model /path/to/npu_model \
  --op-timing /path/to/new-facts/model-timing.json --op-timing-sha256 OP_SHA
```

Replace `OP_SHA` with the lock's digest. Add `--pairs FILE --pairs-sha256 SHA` for confirmed pair/chain evidence and `--composed FILE --composed-sha256 SHA` for its composed side file. Composed evidence also requires its complete pinned base-pair file. Use `--model-region FILE` for representative DRAM input: JSON with `address`, `initial_hex` and optional `expected_hex`; repeat it for disjoint regions. Output directories must be empty. Derivation and evidence tools reject parent traversal and symlinks in input/output ancestry; model manifests fail if an excluded path name is present instead of silently omitting it.

`lib/AtlasModelTiming.cpp` implements the provider interface in `include/Atlas/AtlasTimingProvider.h`. Its costs guide virtual scheduling, allocation proposals, physical scheduling, delay slots, DMA waits and virtual-to-machine lowering. Scalar-slot save/restore/copy proposals combine address-materialization instruction costs with derived scalar load/store timing and releases. Missing facts cause refusal.

DMA proposals replay cold isolated transfers using derived startup, request interval, endpoint latency, fractional response pacing, rounding and finite pending capacity. This assumes pure read or store history and no VMEM grant denial; full native scoring decides the winner. Completion still requires explicit matching waits. The separate RTL target contract has eight DMA command slots: launch n reuses launch n−8's slot. The NPU Model does not enforce this ring, so the compiler moves a still-pending launch n−8's wait immediately before launch n and rejects streams that could overwrite a pending slot. `builtin` does not apply this ring rule; its pre-existing ring findings remain.

The stream scheduler fills a branch/jump delay slot with the block's last-issued single-cycle scalar ALU operation if it completes at issue and nothing later depends on it; otherwise it emits a NOP.

`tools/atlas_model_selection.py` compiles and verifies each candidate, then executes verified word streams on the unmodified native NPU Model in parallel processes. The scorer checks source, numerical-data and effective configuration identities against emitted evidence. Runtime errors, bank conflicts and supplied expected-output mismatches are fatal. Scores are cold cycles from first issue through drained ECALL. The emitted program is the scored program. `--workers` defaults to the smaller of 12 and the available CPU count (the library default is 12); lower it on shared hosts. Each scoring process uses one Torch thread.

Initial candidates cover the default, lookaheads 1/2/4, eight fixed random seeds, source-position waits, DMA staging-window variants and seeded legal MREG allocation ranks. The `full` preset adds single-operation and dependency-group reorderings, followed by PACK reload and selective-wait preload alternatives. Groups contain at most four nodes. Every candidate uses normal allocation, lowering and verification. A compiler-refused candidate records its error stage and cannot win; refusal of every default/lookahead/seed candidate stops with “no legal candidate.” A verified candidate's scoring failure stops compilation.

`--search-budget full` is the default: at most 32 initial, 96 single-operation and 204 group attempts. Decisions use deterministic batches of 12; a strict improvement restarts the neighborhood, and 96 consecutive nonimproving attempts stop a phase. `--search-budget selection` allows up to 24 initial attempts with no order search or PACK alternatives. Individual budget/Boolean flags override presets. Budgets count refused attempts and bound attempts rather than wall time.

Under curve, legal order proposals are ranked by cold replay of derived operation/DMA costs and exposed frontend waiting. Each order may try default and source-position wait placement, letting ready PACK/current-tile work precede future-transfer waits. Retained complete orders are bounded by the remaining attempt budget; estimating eligible orders still scales with neighborhood size. This ranking cannot choose a winner without native scoring.

Profiles define the objective. `curve`, the default, uses the selected model's default curve memory backend. `--profile fifo43` is a separately authored synthetic target: fixed-memory latency 43, one cycle per beat, and request acceptance on cycles 0–3 of each 11 (43/1/11/4), intended to match the standalone AtlasCore harness. These values are compiler literals, not extracted model-default facts. Exact curve-cycle ties are scored under FIFO43; equal scores on both profiles keep the earlier canonical candidate. This comparison applies to every incumbent and search restart. Explicit FIFO43 selection minimizes FIFO43 cycles alone. A curve improvement can increase FIFO43 cycles.

`--guarded-pack` converts eligible PACKs to MXU operations before selection. PACK overlap/reload/preload alternatives apply to PACKs that remain. `selection.json` records candidates, scores, failures, decision parents, accepted moves, tie participants and compile times; selected and candidate artifacts are retained.

## Updating for NPU Model changes

If derivation refuses or validation fails, identify the changed source and classify the change: a refactor may need extractor/source-shape updates; a timing change needs newly derived costs and validation; a new operation needs probe, schema, derivation and compiler mapping coverage. Review the relevant extractor and source contract together, and refresh accepted source shapes only after validating the revised extraction against native executions. Updating a pin alone does not establish support.

To change a supported timing parameter, edit the selected model configuration (for example `dma_memory_params["frequency_ghz"] = 0.75`), derive into a new directory, then compile/select with that same model and the new facts file/digest. Run representative native validation and retain the changed identities. An unsupported architecture change, such as `mrf_depth=16`, refuses with a named capability; editing a configuration field that the active model never reads does not change timing.

Derive fresh facts. Unchanged inputs produce identical semantic and file digests, and the existing overlap evidence remains reusable. A model or configuration change requires compilation without the locked overlap catalog; generating a replacement measured catalog is outside this repository. Run compiler/evidence tests, representative selection and builtin identity checks.

## Results and limits

The provider still uses compiler-authored encoding/resource adapters, capability limits for derived ordinary issue and branch/delay timing, and an explicit one-cycle scratchpad response assumption. Weight reads conservatively cover the isolated compute envelope unless admitted overlap supplies a tighter relation; unknown addresses reserve conservative resources. Waits invalidate overlap eligibility and block/control-flow boundaries drain work. Cold DMA and order replays are proposal heuristics with empty queues, pure read/store history, no VMEM grant denial, serialized engine approximations and handwritten edge offsets; native complete-program scoring chooses winners. PACK costs approximate the lowering template and available delay-slot filling; supported scale codes retain an empirical target gate. Search budgets, seeds, allocation ranks, 100000-cycle compiler bounds, 2048-word generated-code policy, spill-rewrite bounds and the 200000-cycle scorer timeout are engineering limits, not newly derived hardware timing.

Production facts require the payload-bound derivation and validation contract described above. Hashes verify selected bytes and identity claims; they do not authenticate an author or independently execute the source derivation at compile time.

The 44 model-selected programs pass retained both-profile numerical checks with same-Core inputs 1,2,1 and the DMA ring checks. Builtin emitted words match the baseline on the checked 115-source corpus and 11 benchmarks in plain/guarded modes; metadata now records `builtin`, and the builtin delay-slot predicate was narrowed to single-cycle candidates without changing these checked outputs. This is corpus identity, not an identity guarantee for all programs. The results demonstrate bounded-search outcomes, without establishing global optimality, compile-time speedup or physical timing.

The curve backend models DRAM bandwidth without address sensitivity. Close model scores can reverse on the SoC: the measured plain MLP selection reduces model cycles from 4,416 to 4,360 while SoC device cycles rise from 5,030 to 5,033. Optimize and validate against the intended profile and target.
