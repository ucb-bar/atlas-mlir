# Model timing

`builtin` retains Atlas's handwritten timing rules (the old `npu-model-rtl-match-v1` ID is still accepted; artifacts record `builtin`). The opt-in `model` provider reads SHA-256-pinned operation and curve-memory facts and optional pair/chain evidence, with isolated operation facts derived from source/configuration and validated against observed runs, while overlap uses supplied measured evidence and handwritten structural rules. Missing coverage, unsupported operands/configuration, stale identities and malformed proofs fail closed. Selecting evidence does not change the default provider. The compiler still supplies architectural mappings and conservative policies; model facts do not establish physical timing qualification.

## Derive and validate facts

Run with the selected model's Python environment (Python 3.14 for the reviewed AST contracts), using a new output directory:

```sh
python -B tools/atlas_model_facts.py --npu-model /path/to/npu_model --out /path/to/new-facts
```

The driver obtains 49 probe operations/operands from `IsaSpec`, derives event windows and reservation releases from the selected source/configuration, then independently observes each operation with zero/nonzero inputs and instrumentation on/off: 98 observed and 98 unobserved numerical runs. Architectural/control traces, progress, drain, event ages and releases must agree; runtime errors remain fatal. Source, numerical-data and tool manifests must remain unchanged. `model-timing.json`, `facts.lock.json`, the validation report and raw observations retain those identities and checks. Use the lock's `op_timing_sha256` when selecting facts.

Curve DMA facts use the selected CurveMemoryBackend configuration converter and pinned curve bytes, guarded by reviewed full backend/DMA AST shapes and raw-source SHA-256 pins. They retain unloaded latency and peak response pacing for every read/write mix, queue capacity, issue-history window, frequency/channel scaling, launch startup, request interval and rounding/reset semantics. The supported controller is unloaded latency with converge=1 and peak pacing; other modes fail closed. An independent fact interpreter checks native backend streams and isolated DMA commands, including concurrent mixed read/write commands, response backpressure, address translation, history/queue changes and scaling. The external validation report binds the fact payload, and its hash and successful probe counts are retained inside the selected whole-facts digest; the compiler validates that selected digest and schema rather than independently authenticating external report bytes. Simulation validates these source-derived facts and scores candidates; it never fits timing values.

Reviewed structural AST hashes reject unknown control flow; supported latency expressions/tables are evaluated from source. VPU derivation uses pure row planners; MXU/LSU/XLU derivation evaluates timing predicates without numerical execution. The MXU observer infers writes from result lookups after successful ticks; it does not observe row IDs. These are isolated disjoint probes; overlap requires separate evidence. Derivation reads the selected model's `DefaultHardwareConfig`; successful derivation does not imply compiler support for a changed configuration. Compilation accepts only the reviewed default configuration: 32×32 geometry and 64 MREGs; register/weight/CSR and VMEM/DRAM sizes and bases; fetch width; DMA channels, beat/transfer/in-flight limits; VMEM bank/bus and off-chip link geometry and pacing; RTL numerics, deterministic initialization and fatal runtime errors; the exact execution-unit classes and `IsaSpec`; and the curve backend with only `curves=ee290sim_vcs_probe.json` and null latency/beat overrides. Compilation and overlap evidence require the lock's configuration identity. Logical MREG release takes effect on the next begin-cycle; VMEM releases describe port windows. Unit holds remain serialized isolated lifetimes until overlap evidence admits a tighter gap. Scratchpad response latency one and conservative weight-slot lifetimes remain explicit assumptions. A changed source/configuration requires fresh derivation and validation; old overlap confirmations do not transfer automatically.

## Select evidence and compile

```sh
atlas-opt input.mlir \
  --select-atlas-model-evidence="op-timing=model-timing.json op-timing-sha256=OP_SHA dma=wait pairs=model-pairs.json pairs-sha256=PAIR_SHA chains=true" \
  --atlas-compile=provider=model -o final.mlir
atlas-emit final.mlir --program-json > program.json
```

Replace filenames and digest placeholders with selected artifacts. Omit `pairs`, its digest and `chains=true` for isolated facts only. Evidence paths, hashes and model identities travel through verification, emission and LLVM handoff. Evidence must be selected before timing; replacing retained evidence or timing metadata is rejected. `dma=wait` requires known captured operands, explicit upper-base configuration and matching completion waits. DMA also requires validated `dma_timing` facts; older operation-only facts remain usable for non-DMA work and fail closed for DMA.

The model provider estimates a cold isolated transfer from source-derived launch startup, request interval, unloaded endpoint latency, fractional response pacing, rounding and finite pending capacity. Physical wait priorities and virtual costs use the same provider callback. This replaces the old calibrated DMA estimate for model; builtin retains its existing estimate. The estimate assumes pure read or store history and no VMEM grant denial, so it guides proposals without establishing completion or predicting a complete mixed stream. Matching waits and full native model scoring remain required. The compiler retains its existing default-configuration scope; validating scaled backend configurations does not automatically admit them as compiler profiles.

Under model the stream scheduler fills a pending branch or jump delay slot as builtin does: with the block's last-issued single-cycle scalar ALU op that completes at issue and that nothing after it depends on, else a NOP. The moved op keeps its scalar replay context, so confirmed PACK scalar overlap still applies. Virtual PACK costs assume the filled slot through the same provider capability.

The RTL holds eight DMA commands in a ring: launch n reuses the command slot of launch n-8, so launch n-8 must be waited first, and the model provider refuses a stream that violates this. Under model, wait insertion therefore also completes a still-pending transfer n-8 immediately before launch n, counting helper launches, which wait at once. Every order the search replays is ring-legal by construction, and the wait moves earlier rather than adding an instruction. The loop guard defensively checks the stream reader invariant that launches stay outside analyzed loops. Outside analyzed loops, redirects and branch targets drain all pending transfers, so counting launches in program order is safe between drain points. Builtin wait insertion is unchanged and applies no ring rule.

`tools/atlas_model_pairs.py` projects a sealed master plus its successful validation receipt into confirmed-only evidence. A fresh per-operation facts digest requires a new projection with `--per-op-sha256 OP_SHA`, and fresh pair/chain replay and composed projection against that same digest; never edit retained proof bindings in place. It preserves supported relations/constraints, original proof identities, swept minima and exact one-short negatives. A pair admission requires an exact ordered operation/relation match within its covered gap interval. Three or more pre-issue-live commands also need a complete exact chain witness, every live pair, issue gaps and post-progress membership. Completed commands remain in the overlap history until the epoch drains; no capacity or prefix/suffix extrapolation is allowed. Scalar PACK overlap additionally requires immutable aligned LW/SW address proofs for all 32 iterations. Register, port, VMEM and DMA obligations remain enforced; waits invalidate earlier overlap eligibility.

Composed evidence is a separate `atlas.model_composed.v1` side file bound to the exact per-op and base-pair digests. `atlas_model_composition.py` replays pair minima/negatives against row footprints; `atlas_model_chain_composition.py` replays complete chains and structural capacities. `atlas_model_composed_projection.py` requires both replay receipts, independent model/RTL holdouts, rejecting controls and the actual query set before projecting bounded engine/relation classes. The consumer checks these identities, positive/negative coverage, exact live-pair coverage and structural capacity. Select with `composed=FILE composed-sha256=SHA` in the evidence pass (or `--composed FILE --composed-sha256 SHA` in the Python driver). This requires the complete pinned base-pair file. Composition requires selected `reservation_releases`; raw measured exports without them fail closed. Pass `--per-op-sha256 SHA` to the projector for validated derived facts; every replay and the base projection must bind that exact digest and the same master. Set `ATLAS_MODEL_LOG_UNMATCHED=1` while compiling to print each unmatched overlap query once as an `ATLAS_MODEL_UNMATCHED` JSON line, the projector's `--queries` input.

## Model selection, banks and local search

`--search-budget full` is the model driver default: at most 32 initial, 96 single-operation and 204 group attempts, followed by PACK reload and selective-wait preload alternatives. It stops a phase after 96 consecutive nonimproving attempts, checked after each fixed batch of 12; every strict cycle gain resets patience. `--search-budget selection` retains the 24-attempt knob-only mode. Individual budgets, Boolean candidate flags and `--search-patience` override presets; zero patience disables early stopping. The direct Python API keeps its explicit opt-in search defaults.

Candidate compilation runs in parallel within each fixed decision batch. Only canonical candidates are compiled and scored; strict winners restart the neighborhood, and ties retain the earlier candidate. Identical emitted words share one score within the selected source/profile/model configuration.

```sh
python -B tools/atlas_model_selection.py input.mlir --output-dir selected --atlas-bin-dir build/bin --npu-model /path/to/npu_model \
  --op-timing model-timing.json --op-timing-sha256 OP_SHA \
  --pairs model-pairs.json --pairs-sha256 PAIR_SHA \
  --search-budget full
```

Model selection is opt-in through this driver or `tools/lower_atlas_program.py --provider model`. Its default scoring profile is `curve`, matching the pinned model's default memory backend; use `--profile fifo43` to select on the retained synthetic FIFO43 profile. The default timing provider remains builtin. Initial attempts cover the default, existing lookaheads 1/2/4, eight fixed random seeds, source-position waits and uniform free DMA staging-window ranks. Repeatable `--store-windows 0,1,3` adds explicit vectors. Bank candidates add eight seeded MREG rank vectors on the best schedule, within the initial candidate cap; the receipt records `mreg_pool_size`. Each rank selects only an allocator-free color under the existing interference/reservation/BF16 rules. Banks and explicit order replay require model; builtin compiles once without scoring.

`--search-evaluations N` (full 96; selection 0) adds at most N legal single-operation insertions from the best initial candidate, including its bank choices. Fixed shuffled neighborhoods and batches of 12 preserve worker-count determinism. Strict cycle improvements restart the neighborhood; ties keep the earlier program. Rejected attempts count against the budget, and exhausted neighborhoods stop early. Every replay preserves SSA, implicit state, DMA alias and MXU-slot edges and rethreads state before the normal spill/lower/verification pipeline. `--workers` defaults to the lesser of 36 and the host CPU count; budgets bound attempts, not wall time. `selection.json` records candidates, scores, failures, decision parents, accepted moves, cache counts and compile times; every emitted candidate and the selected words are retained.

Curve selection ranks the complete legal single-operation and group neighborhoods by a cold replay of the provider's derived operation and DMA costs, then by exposed frontend waiting. The graph carries the selected facts digest and native replay totals; the driver checks both before using its costs. Stable ties preserve the existing deterministic neighborhood order. Each order, including the incumbent, can try default and source-position wait placement within the existing attempt budgets, allowing ready PACK and current-tile work to precede future-transfer waits. Every candidate retains completion waits, ring-safe DMA waits and normal verification; only full native model scores can select it. `--no-curve-candidates` disables this proposal policy for comparisons. FIFO43 retains its existing neighborhood policy.

The model driver continues when the compiler refuses a candidate at compile or emit, including the default: the row records the error and its `error_stage`, it cannot win, and `default_cycles` is null for a refused default. A verified program that fails model scoring stops the compilation, as does a refusal of all 12 default, lookahead and seed candidates ("no legal candidate"); `selection.json` is written first.

`--search-group-evaluations N` adds a separate optional budget after local search (full 204, selection 0; model only). An insertion moves its node with every crossed predecessor when hoisting, or successor when sinking, retaining both groups’ original order. Groups exceeding four nodes are rejected. All graph edges, compiler verifiers, fixed batches and strict model-cycle improvement checks still apply; no timing admission changes. The receipt records this phase under `group_search`.

`--pack-reload-candidates` scores one additional candidate after order search, retaining the incumbent on ties or failure. The model-only lowering option `pack-reload-after-weight=true` places a pending legacy matmul weight load before its activation PACK's trailing reload when that reload remains the same block's final emitted span. This can overlap the weight push with activation-load completion. Existing facts and verifiers still decide timing legality; labels, operation tags and allocations are preserved. The full preset enables this alternative; builtin and the low-level lowering option retain their defaults.

`--pack-preload-candidates` additionally scores preloading an adjacent legacy matmul's pending weight before PACK with `pack-weight-before-pack=true` and `wait-placement=preloaded`, preserving only those loads' DMA waits at their source positions. The original allocator must place the weight outside both PACK input halves and its output. Candidate-only `atlas.model_preloaded_weights` records the transfer IDs; selective wait placement adds ordering edges and rejects malformed or missing IDs. Other waits retain the existing scheduling policy. This alternative clears `pack-reload-after-weight`, keeps all existing timing/resource checks, and wins only on strictly lower model cycles. It adds no timing admission; the full preset enables it.

The driver executes each distinct verified word stream on `--npu-model`, checking its source, numerical data and effective default configuration against the emitted provider evidence. `--model-region FILE` supplies representative DRAM input (`address`, `initial_hex`, optional `expected_hex`); repeat it for disjoint regions. Scores are cold cycles from first issue through drained ECALL. Runtime errors and bank conflicts are fatal; supplied expected DRAM bytes must match. `curve` resolves the curve from the selected model and is the default; explicit `--profile fifo43` uses latency 43 and request acceptance on cycles 0–3 of each 11. Separate processes score candidates in parallel by executing the complete native Core; the cold proposal replay never supplies a selection score.

`tools/lower_atlas_program.py --provider model --guarded-pack` and the standalone `tools/atlas_model_selection.py --guarded-pack` pass guarded PACK conversion through model preparation before candidate selection. `selection.json` records the requested mode as `guarded_pack`. Converted PACKs use MXU operations; PACK overlap and reload/preload candidates apply to PACKs that remain unconverted. Tiled selection integration tests require both `ATLAS_TEST_OP_TIMING` and `ATLAS_TEST_PAIR_TIMING` evidence files; ordinary discovery skips them when the external pins are unset, and configured missing files fail.

Pair and chain overlap use a supplied simulation-measured catalog pinned to model revision `9e6313b` and the locked configuration, plus handwritten capacity, port, weight/accumulator and alias rules. These tools project/replay the supplied catalog; this repository cannot regenerate its measurements. Other revisions have no overlap evidence and must use isolated lifetimes. Re-projection is allowed only for unchanged timing/model content, and binds the supplied catalog to the exact new facts digest. Wall-clock validation times and tool hashes make that digest change even when timing content is unchanged.

Builtin emitted words remain unchanged on the checked plain/guarded corpus; recorded provider metadata is `builtin` and the delay-slot predicate now requires a single-cycle candidate, so this is corpus identity rather than a guarantee for every input.
