# Exact source float device regions

The Atlas target admits dense pointwise `bf16_to_f32`, `f32_to_bf16`, `bf16_neg`, `f32_neg`, `bf16_add`, and `bf16_sub` requests with exact raw-bit numerical policies and identity maps. Boundary inputs are external tensors. Constants, binary64, layout overrides, and different policies are rejected by this lowering. The application selector retains its existing routes for other requests.

BF16 add and subtract require one IEEE round-to-nearest-even step. The lowering reuses the qualified residual DAG from `qualified_rne_add.py` when every operand is signed zero or has magnitude code in `[0x2f80,0x4f80]`. Otherwise, normal-or-zero operands can use the FP32 pair-row `row_sum` route from `rne_add.py`. Two negative zeros bypass that route. Pair results remain private until every candidate is normal or a provably exact zero; a subnormal, infinity, or unjustified zero triggers scalar fallback for the tile. These admission checks preserve the numerical premises of the reused vector routes.

The scalar fallback orders BF16 magnitudes, aligns eight-bit significands with 16 guard bits and a sticky bit, performs signed magnitude addition or subtraction, normalizes with eight fixed steps, and rounds once. Alignment loses bits only for exponent gaps above 16, where cancellation cannot require left normalization. Exact cancellation produces positive zero; two negative zeros produce negative zero. Infinities retain their signs, and finite overflow rounds to infinity. BF16 expansion shifts the encoding left by 16 bits. F32 narrowing adds `0x7fff + (high & 1)` before taking the high word. Sign flips XOR only the sign bit and preserve NaN payloads.

Checked leaves scan their entire source domain before any result DMA store. They reject NaNs and invalid infinity cancellation, writing a fixed 32-byte device status buffer. Sign flips accept every encoding. The public Atlas status is `DOMAIN=2`; the host C oracle uses `-2`. Tests compare their error classifications and require the external logical output to remain unchanged after rejection.

Device bodies use counted tile loops. Casts and negations use compact counted-lane loops unless `--exact-float-unroll` expands the bounded inner tile into fixed-offset slot accesses; the complete preflight pass still precedes result stores, and the program-size cap is an independent admission limit, not a selector. BF16 add/sub keeps its runtime-indexed lane loops.

BF16 add and subtract first check each tile for the qualified vector domain, which contains only signed zeros and bounded normal values, so admission also proves validity. Only refused tiles run the broader validity and pair-row checks. The complete input is validated before any result is written. The opt-in route table, lane groups, and vector preflight are described in [native options](native-options.md).

BF16 arithmetic processes complete 1,024-element tiles; casts use up to 512 lanes when either side needs four bytes. Short leaves use a 32-lane-aligned prefix, with private zero padding. Pair-row arithmetic gathers and checks 32 rows at a time inside the tile. Named scalar SSA values pass through the same scheduling, allocation, spilling, DMA-wait, and delay insertion pipeline as vector work. There is no independent physical stream generator. Expanded kernels trade larger instruction images for fewer device instructions; device-cycle measurements do not include host instruction-upload latency.

The application schedule divides large requests into bounded leaves and reuses bodies for equal slice sizes. The default leaf maxima are 1,024 elements for add/sub, 20,480 for BF16 widening, 18,432 for FP32 narrowing, and 43,008 for sign flips, further limited by the selected I/O window. The compiler independently proves each emitted body's worst-case instruction bound, including its exceptional arithmetic paths. Host dispatch checks pointers, copies bytes, fills private padding, launches device programs, and reads device status. Successful leaf outputs accumulate in private staging. A shared slice dispatcher publishes the complete logical result only after every leaf succeeds, so a rejected final slice also preserves bytes covered by earlier successful slices. Application wrappers compile add/sub with private results: each tile is validated and computed while resident, an invalid tile makes the status sticky and stops later stores, and the wrapper discards the whole result on failure; raw device compilation stays two-pass. This private-result contract is recorded in the plan and manifest and authenticated in source replay and rebinding. Private slices are sized by a conservative per-tile envelope and split into equal aligned slices when that keeps the minimum invocation count; replay keeps a saved slice size and refuses a malformed, misaligned, or oversized one.

Every body is checked by the standard generated schedule, machine stream, DMA, tile, CFG, memory initialization, buffer, address, and timing contracts. Runtime slot indices are bounded in element units and lowered through the common slot operation family. Scalar variable shifts require a proven range below 32.

Stored and executed instructions have separate limits. At the selected RTL revision `0079c0541111197741a231c002e3843fa6f545b2`, `ScalarCore.scala::AtlasMemMap` declares `IMEM_SIZE = 0x0002_0000` and `diplomatic/memory/InstrMem.scala` instantiates `SyncReadMem(IMEM_WORDS, UInt(32.W))`, so a program holds at most **32,768 four-byte instructions (128 KiB)**. The generated-stream verifier derives this capacity from `runtime/selected-host-map.json`; `--program-size-limit-bytes` can only lower it.

The software execution budget defaults to 1,000,000 instructions per launch. `native-compile --execution-instruction-limit N` selects another positive budget, independently of IMEM, and records it in the compilation identity and the replayed instruction-bound report; use the same option for `native-verify`. Larger budgets scale the slice policy, subject to the I/O window and, for raw leaves, the 512-tile route table. Every emitted image still needs a finite worst-case bound below the budget, and compiler admission does not raise a simulator's watchdog.

C export authenticates the complete source request, slice mapping, leaf inventory, and manifests, then replays virtual compilation and binary emission. Execution plans describe immutable input spans and mutable private result/status spans, including padding. Rehashing changed slice metadata cannot change the source schedule checked by export.

Directed, seeded, and exhaustive unary tests (`test_exact_float_unary_tiles.py` covers every BF16 negation and widening encoding) compare against an independent host C oracle. These are functional checks, not cycle or RTL measurements, and they do not establish exhaustive correctness over all operand pairs or F32 encodings.
