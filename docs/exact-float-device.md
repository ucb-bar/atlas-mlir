# Exact source float device regions

The Atlas target admits dense pointwise `bf16_to_f32`, `f32_to_bf16`, `bf16_neg`, `f32_neg`, `bf16_add`, and `bf16_sub` requests with exact raw-bit numerical policies and identity maps. Boundary inputs are external tensors. Constants, binary64, layout overrides, and different policies are rejected by this lowering. The application selector retains its existing routes for other requests.

BF16 add and subtract require one IEEE round-to-nearest-even step. The lowering reuses the qualified residual DAG from `qualified_rne_add.py` when every operand is signed zero or has magnitude code in `[0x2f80,0x4f80]`. Otherwise, normal-or-zero operands can use the FP32 pair-row `row_sum` route from `rne_add.py`. Two negative zeros bypass that route. Pair results remain private until every candidate is normal or a provably exact zero; a subnormal, infinity, or unjustified zero triggers scalar fallback for the tile. These admission checks preserve the numerical premises of the reused vector routes.

The scalar fallback orders BF16 magnitudes, aligns eight-bit significands with 16 guard bits and a sticky bit, performs signed magnitude addition or subtraction, normalizes with eight fixed steps, and rounds once. Alignment loses bits only for exponent gaps above 16, where cancellation cannot require left normalization. Exact cancellation produces positive zero; two negative zeros produce negative zero. Infinities retain their signs, and finite overflow rounds to infinity. BF16 expansion shifts the encoding left by 16 bits. F32 narrowing adds `0x7fff + (high & 1)` before taking the high word. Sign flips XOR only the sign bit and preserve NaN payloads.

Checked leaves scan their entire source domain before any result DMA store. They reject NaNs and invalid infinity cancellation, writing a fixed 32-byte device status buffer. Sign flips accept every encoding. The public Atlas status is `DOMAIN=2`; the host C oracle uses `-2`. Tests compare their error classifications and require the external logical output to remain unchanged after rejection.

Device bodies use counted tile loops. Casts and negations expand the bounded inner tile into fixed-offset slot accesses and share scalar constants within each straight-line block. This removes per-element loop control and address arithmetic while keeping the complete preflight pass ahead of result stores. An explicit `CodegenOptions.program_size_limit_bytes` retains the compact counted-lane implementation, so a smaller image budget does not force expansion. BF16 add/sub keeps its runtime-indexed lane loops.

BF16 arithmetic processes complete 1,024-element tiles; casts use up to 512 lanes when either side needs four bytes. Short leaves use a 32-lane-aligned prefix, with private zero padding. Pair-row arithmetic gathers and checks 32 rows at a time inside the tile. Named scalar SSA values pass through the same scheduling, allocation, spilling, DMA-wait, and delay insertion pipeline as vector work. There is no independent physical stream generator. Expanded kernels trade larger instruction images for fewer device instructions; device-cycle measurements do not include host instruction-upload latency.

The application schedule divides large requests into bounded leaves and reuses bodies for equal slice sizes. Add/sub uses at most 1,024 elements per slice: unchanged `npu_model` measured 630,889 instructions for add and 641,129 for subtract on the exceptional route, while both 2,048-element trials reached the unchanged 1,000,000-instruction limit; the other operations use at most 2,048 elements per slice. Host dispatch checks pointers, copies bytes, fills private padding, launches device programs, and reads device status. Successful leaf outputs accumulate in private staging. A shared slice dispatcher publishes the complete logical result only after every leaf succeeds, so a rejected final slice also preserves bytes covered by earlier successful slices.

Every body is checked by the standard generated schedule, machine stream, DMA, tile, CFG, memory initialization, buffer, address, and timing contracts. Runtime slot indices are bounded in element units and lowered through the common slot operation family. Scalar variable shifts require a proven range below 32. The default functional instruction budget remains 1,000,000; no bound is raised for these bodies.

C export authenticates the complete source request, slice mapping, leaf inventory, and manifests, then replays virtual compilation and binary emission. Execution plans describe immutable input spans and mutable private result/status spans, including padding. Rehashing changed slice metadata cannot change the source schedule checked by export.

Directed and seeded tests cover rounding ties, signed zeros, subnormals, extrema, infinities, shared operands, late invalid lanes, source metadata changes, and machine instruction mutations. Large exponent-gap and midpoint sweeps execute verified emitted ISA in a branch-local C interpreter against the original host C oracle. Separate unchanged `npu_model` execution checks the exported ABI and samples the interpreter's vector semantics. Receipts identify the source head, working-tree status, and swept program hashes. These are functional checks, not cycle or RTL measurements, and they do not establish exhaustive correctness over all operand pairs or F32 encodings.

`test_exact_float_unary_tiles.py` checks every BF16 encoding for negation and every admitted encoding for widening against the independent host reference. Narrowing covers both signs, every finite exponent, rounding ties on even/odd high words, and seeded random words. Tile/leaf tails and invalid values at the first, middle and final positions check rejection before publication. Explicit 4 KiB image caps exercise the compact route.
