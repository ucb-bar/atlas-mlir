# CFG DMA timing proof

`--verify-atlas-timing` proves pending-transfer ownership with `checkAtlasDMACFG`, subject to the selected provider's footprint and DMA-size preconditions, before the existing issue-spacing, reservation, and fixed-latency drain checks. Scheduling preflight keeps `checkAtlasStream` and its existing scope. Generated DMA wait insertion completes a slot's pending owner before another launch reuses it.

The abstract domain is a bounded disjunction of correlated register environments and pending launch snapshots. Each register is a singleton RV32 interval or the full RV32 interval. A disjunction retains relations such as `(current, next) = (base, base + stride)` or `(base + stride, base)`, without replacing the buffers by independent sets. This is finite interval reasoning, rather than symbolic affine recurrence solving. Scalar instructions use the existing RV32 transfer functions. Entry registers, unconstrained loads, CSR results, and link results are unknown unless defined by the modeled scalar instructions; x0 is zero. No reset assumption, tensor value, kit identity, or sampled execution supplies facts. Explicit DRAM inputs are conditional invocation assumptions as described below.

The CFG worklist starts at block zero. Blocks unreachable from block zero are not checked for DMA hazards or delay-slot legality by this analysis. This is safe because restart resets the PC to the stream entry, ECALL and EBREAK latch the halted state, and execution cannot enter the middle of a stream. The fixed-latency phase still checks every block for spacing. Known scalar branches select their actual successor; unknown branches explore both. The branch reads its predicate before its delay slot executes. Direct jumps, fall-through, halt, and branches to the stream end have explicit edges. Pending launches cross arbitrary CFG edges. A launch is rejected if its channel already has a pending transfer, because the RTL clears the channel busy bit when any slot on that channel retires; one wait cannot safely cover multiple outstanding launches on the same channel. A matching-channel wait releases that channel's pending ownership. Halt, publication, and feasible exits require empty pending ownership. The analysis checks every current footprint against every pending footprint with the selected provider's unchanged `dmaConflict` rule.

Pending state is keyed by static launch instruction and captures register operands at launch. Reusing a register cannot rewrite a captured address. A repeated dynamic launch must first release its channel with a wait. Joining and widening may merge snapshots of one static launch from different paths, retaining all possible addresses. Different channels and different static launches remain separate obligations.

Each path also tracks the next command-ring slot modulo eight and each slot's possible channel owners. A launch must target a free slot because `diplomatic/memory/DMA.scala:223-228` overwrites the free-running enqueue index without checking occupancy, and retirement clears the channel recorded in that slot (`316-319`). A matching wait clears only its channel's slot ownership. A full drain permits rebasing the relative index to zero without assuming a hardware index reset. Widening unions slot owners and makes disagreeing indices unknown; a subsequent launch with an unknown index requires every slot to be free.

At 65,536 distinct environments per block, widening replaces the disjunction by one componentwise interval hull and the union of pending launch keys. A disagreeing register becomes the full RV32 interval; it never becomes a new guessed constant. Captured snapshots widen the same way. The built-in provider maps unknown addresses to `anywhere` accesses, so forgetting a value can only lose disjointness proofs. Other provider identities fail closed at this limit. For pending-transfer ownership, this bound trades precision for cost. Size validation is limited to known sizes; widening can forget a size and therefore does not preserve all known-size rejections. The public helper accepts a smaller bound for directed unit tests.

For soundness, induct on CFG transitions. The initial abstract state includes every possible restarted-core register state. Scalar transfer includes every concrete result, branch pruning removes only an impossible edge, and each captured pending snapshot includes the operands of every unwaited transfer it represents. Wait kills only its own channel. Joining and widening overapproximate both register values and pending ownership, including a transfer present on only one predecessor. Every processed abstract state checks all represented completion conflicts and exits. Work terminates because each block stores a bounded exact set, then ascends a finite lattice: registers can become unknown only once, and pending keys can only be added. Acceptance occurs only after the worklist empties, including a final check that unsupported widening did not drop the last edge. Therefore every reachable transfer/access pair is covered by a successful provider check, subject to the provider's footprint and DMA-size preconditions; this does not prove universal validity of dynamic sizes.

The built-in provider rejects a known DMA size of zero, a size not divisible by 32 bytes, or a size of 8192 bytes or more. The RTL captures a 13-bit transfer size and requires complete 32-byte beats; a zero beat count can underflow its termination counter. Unknown sizes retain a conservative `anywhere` VMEM footprint and may be accepted when followed by a matching wait. The caller must ensure every dynamic size is nonzero, divisible by 32 bytes, and within the direction-specific limits below; acceptance does not establish these properties for an unknown size.

Known stores additionally reject sizes above 4096 bytes: `atlas/common/DmaParams.scala:28-37` sets a 128-beat store queue, and `diplomatic/memory/DMA.scala:196-210` issues VMEM reads and enqueues their results without observing queue readiness, so TileLink backpressure can overflow larger stores. Loads retain the aligned 8160-byte limit because their beat counters cover the 13-bit size range (`diplomatic/memory/DMA.scala:120-121,164-166`), their requests bypass the store queue and throttle in-flight beats (`237-240`), and their responses honor VMEM backpressure (`286-293`).

This proof is relative to the selected timing provider. It does not add DRAM alias rules, change the provider's conservative VMEM alignment and capacity restrictions, prove host accesses, or qualify the provider against hardware. The fixed-latency verifier still checks every emitted block with its existing conservative entry facts and requires fixed-latency work to drain at CFG boundaries. The removed DMA boundary checks duplicated the old one-block DMA scope; their ownership obligation is now discharged across the CFG. The DELAY-before-halt rule remains unchanged. Diagnostics remain fail-fast.

Tests include correlated alternating buffers, cross-block waits, captured-pointer overwrites, known and unknown branches, signed and unsigned predicates, predicate-changing delay slots, dead exit edges, matching-channel ownership, actual and unknown overlaps, pending exits, conservative widening, unsupported provider overflow, fixed-latency drain, and DELAY-before-halt. CLI fixtures use a small counted prefetch loop and inject a one-operand overlap into its paired negative case.

## Explicit DRAM input contract

Program words alone cannot constrain host-populated DRAM values. An optional module attribute supplies exact immutable DRAM words for one invocation:

```mlir
atlas.dram_contract = {name = "synthetic-input-v1", words = [
  {address = 2415919104 : i64, value = 16384 : i64}
]}
```

Addresses are unique, word-aligned unsigned 32-bit byte addresses; values are unsigned 32-bit words encoded as i64. A nonempty name and words array are required. The caller promises these words equal the supplied image and remain unchanged throughout execution, including against host and external writes. This is an input assumption, not a proof of host concurrency or a fact inferred from a program hash. Contracts are supported only with the built-in provider.

All VMEM initially remains unknown. A completed DMA load with known aligned source, destination, length, and zero upper DRAM address word copies matching contract words into sparse VMEM facts. Launches invalidate destination facts immediately; matching waits establish copies. Scalar LW can recover an exact word. Scalar stores, vector stores, and other VMEM writes invalidate every potentially overlapping fact. Unknown writes forget all facts. Device DMA stores that may overlap contracted DRAM reject, including stores with unknown address operands. Joins retain only identical VMEM facts present on every predecessor. After widening, DMA completion never establishes new constants because a unioned pending key may have executed on only some represented paths.

Successful timing passes retain `atlas.timing_assumptions = ["immutable-dram:<name>"]`; JSON emission retains both the input contract and recorded assumptions.
