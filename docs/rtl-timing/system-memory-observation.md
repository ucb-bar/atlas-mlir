# Finite system memory observations

`tools/check-ee290-system-memory-observation.py` independently decodes an explicitly pinned EE290SimConfig capture receipt and its VCD. The authored projection has 356 signals: the existing 39 boundary signals, five VMEM competing request valids, fourteen MREG competing request valids, six VMEM SRAM bank ports and 32 MREG SRAM bank port pairs. It accepts no caller-supplied signal remapping.

Run `python3 tools/check-ee290-system-memory-observation.py --capture-report CAPTURE --expected-capture-sha256 SHA256 --output NEW_DIRECTORY`. The output must be a fresh ignored directory beneath `build/rtl-timing`. The packet binds selected capture/plan/boundary-plan/trace identities, records validator snapshots, and publishes its success state only after a final identity stability check. It sets `capture_execution_link_verified` and `scheduling_qualified` false: the separate aggregate checker establishes production, simulator/program and numerical relationships.

The public API `analyze_trace(trace_path, scope, max_edges=3000000)` returns schema `atlas.ee290_system_memory_events.v0` with validator `atlas.ee290.system_memory.fixed356.v2`. It recomputes boundary observations with the existing decoder, then uses a private fixed projection to validate each continuous execution envelope from observed halt deassertion through ECALL/halt inclusive. Those envelopes cover scalar setup, both commands, command-release edges, all inter-command and pre-marker delays, marker publication and terminal acceptance. Every admitted sample requires all nineteen pre-arbitration competitor requests known zero, matching six VMEM and 32 MREG physical enables, and all seventy direct SRAM clocks known low before the edge with exactly one actual rise at the corresponding global rising timestamp. A bounded parallel VCD scan verifies those transitions while preserving the existing pre-timestamp sampling convention; frozen, unknown, missing, mistimed or repeated clock transitions reject the trace. Each window records `sampled_sram_clocks_rise_at_global_edge: true`. Active SRAM bank/row, write data/mask and physical read-response data are validated by the existing SRAM checker. Inactive data may remain unknown; unknown active controls or consumed data reject the trace. Adjacent commands on a preceding command's release edge remain supported.

These are sampled finite behavioral SRAM observations. Pre-timestamp rising-edge sampling does not certify delta ordering, asynchronous/off-edge clock glitches, physical macro/PVT timing, unseen requester paths or a general operand/program domain. Observed halt deassertion is an envelope endpoint, not proof of universal accelerator entry quiescence. Host CSR status polling is permitted; instruction/debug-register immutability and input initialization require separately bound host fixture reasoning. The checker does not infer these properties from a copied success flag.

Focused mutation tests run with `python3 -m unittest discover -s test -p 'test_ee290_system_memory_observation.py'`. They cover competitor requests at entry/terminal, unknown consumed values, masks/addresses/data, missing/extra and idle physical enables, sampled clocks, truncated windows and denied symlink targets. Complete VCD tests pass valid independent and aliased clocks and reject frozen clocks, missing or late rising edges, unknown transitions and multiple transitions at one timestamp. Actual baseline/scheduled capture validation additionally exercises the complete VCD/boundary decoder.
