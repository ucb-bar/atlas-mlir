# Bounded EE290SimConfig applicability

`tools/check-ee290-bounded-applicability.py` revalidates the selected source correspondence, retained manifest/hardware, conditional VLS report, compiler witness, and baseline/scheduled component replay/SRAM receipts. Every selected receipt and the executing `atlas-emit` binary require an explicit SHA-256 through the corresponding `--expected-…-sha256` option. Run `--help` for the complete selection interface; `--output` must identify a fresh ignored directory beneath `build/rtl-timing`.

The checker recomputes the bounded source recipe with the existing pure source validator, binds historical producers to their executed snapshots, and compares the location-normalized AtlasCore closure. It does not rerun elaboration or lowering. It verifies selected simulation RTL and behavioral memory snapshot inventories/content, captured compilation inputs/source arguments and harness, and the compiled executable/program/trace relationships. Existing boundary and SRAM decoder/checker functions re-read the trace and compare all stored observations to their recomputed results. Copied pass flags alone cannot accept the replay.

A caller-pinned `atlas-emit --rtl-timing-json` runs on each selected final program and uses the existing final verifier and shared resolver. Its selected evidence hashes, resolver identity, conditional policy, instruction words and little-endian word digest must match the compiler/replay selection. The result records the exact export invocation, exit status, stdout/stderr identities and selected final MLIR identity. It compares the measured VLS op/mreg/line operands, relative issue gaps, source/destination stream ages, read responses, inclusive path hold release and marker/terminal edges directly against that export. It introduces no additional timing table or numerical evaluator. Validator identities are pinned before validation and their execution snapshots are copied into the new packet.

Optional paired `--verilog-derivation` and `--implicit-ram-correspondence` selections, each with its expected digest, recompute byte/content correspondence for the 119 standalone selected modules and two implicit RAMs, bind these to both compiled snapshot selections, and check declared FIRRTL/annotation/lowering-option command relationships. This is content and command metadata correspondence; the packet retains `generation_execution_proven: false` and `source_to_simulation_complete: false` because no captured derivation execution proves the generation edge and four external behavioral memory implementations remain assumptions. Omitting this pair records content correspondence as unverified.

The output schema is `atlas.ee290_bounded_applicability.v0`, with state `finite_observations_validated`, conditional qualification and `scheduling_qualified`, `system_qualified`, and `operand_domain_qualified` all false. Acceptance covers the recorded operands and command windows on the selected two-state AtlasCore model and behavioral SRAM wrappers with direct full-line host TileLink accesses. Granted physical bank enables are checked, but losing/suppressed same-bank competitors and activity outside observed windows remain unexcluded. General operand coverage, opaque framework and system runtime closure, physical macro/PVT timing and full CPU/system applicability remain assumptions or missing evidence. The integrated VCS numerical pair has no internal boundary trace and cannot extend this acceptance scope.

Run focused rejection tests with `python3 -m unittest discover -s test -p 'test_ee290_bounded_applicability.py'`. A complete selected-evidence invocation also reruns the existing boundary/SRAM checkers and writes their recomputed receipts beneath the new output directory. Existing frozen receipts and producers are never rewritten.
