# Guarded BF16 to FP8 conversion proposal

`atlas-opt --lower-atlas-guarded-pack` explicitly selects an alternative implementation of `atlas.virtual_pack_fp8`. It acts before allocation, input-to-DMA conversion and virtual scheduling. Existing pipelines remain unchanged unless the pass is requested.

Only single-block functions are rewritten; multi-block functions and standalone streams are unchanged. The existing virtual verifier permits only i1/i32 entry arguments, prohibits accumulator block arguments and cross-block handle captures, and requires each accumulator to be consumed before block exit. The pass verifies that contract before counting live selected-unit accumulators, so no incoming handle is omitted from its slot accounting. More general CFG resource analysis is outside this proposal.

The pass converts scale codes 0 through 255 when the exact BF16 source is finite. For codes `s=0..246`, it clamps to positive BF16 bits `((s+8)<<7)|96` and the corresponding negative bound, loads the tile into a selected MXU BF16 accumulator, and reads it out as FP8 with inverse scale code `254-s`. At code 127 these bounds are ±448. For codes 247 through 255, it omits the clamps and uses inverse scale code `254-min(s,254)`; retained hardware codes 254 and 255 alias. Constants are shared only for the same PACK code within each block. The pass threads the existing state through the new accumulator operations. It keeps PACK if both selected-unit accumulator slots are live. Existing state, resource, allocation, machine metadata and timing verifiers check the resulting ordinary virtual operations. Contractions and arithmetic policies are unchanged.

The default conversion unit is MXU0, selected from full-clamp measurements on the retained RTL harness. `--lower-atlas-guarded-pack=unit=1` requests MXU1 explicitly. This option selects the conversion engine only; it never moves a contraction. Engine ranking is memory-backend dependent and requires measurement on the intended target.

The retained converter equations establish equality for all non-NaN BF16 encodings at codes 0..246 with these clamps, and for all BF16 encodings at codes 247..255 without clamps. Low-code clamping changes NaNs, so the pass requires the stronger finite premise. It conservatively keeps that same finite-source requirement at high codes, even though their all-bit equation proof permits a broader rewrite. This proposal makes no engine-ranking claim for a different memory backend. The frozen native PACK lowering and oracle admit only codes 122..128: when this pass retains PACK because a contract or resource is unavailable, downstream native lowering may still reject other codes. The opt-in rewrite does not expand native PACK admission.

## Source contract

The optional unit attribute `finite_src` on `atlas.virtual_pack_fp8` is an explicit caller precondition. For every execution of that operation, every lane of its exact `src` SSA value must be finite. A source containing this promise has undefined behavior if the caller violates it. The attribute adds no runtime check and does not prove the producer's arithmetic safe. Its scope is this operation's source operand, not another producer, another PACK or a name-based graph match. Frontends must establish the premise analytically or impose and document sufficient public input preconditions; fixture observations cannot establish it.

```mlir
%packed = "atlas.virtual_pack_fp8"(%producer) {finite_src, scale_code = 127 : i32} : (!atlas.virtual_bf16) -> !atlas.virtual_fp8
```

Without that explicit contract, a small SSA abstract interpretation classifies every lane using a closed interval in the hardware's raw BF16 total order. Unknown values span both signed NaN tails. Finite means the interval excludes infinities and NaNs; nonnegative admits either zero sign and positive infinity but excludes NaNs; unit interval means finite values in [0,1], including either zero sign. Nonnegative alone never implies finite. The analysis follows SSA definitions, not names, fixture values, graph topology, or user-supplied fact attributes. It memoizes facts within a single block and does not propagate a PACK caller promise to its producer or another PACK.

Raw BF16 splats supply exact intervals, mov and BF16 accumulator copy preserve them, and min/max apply interval min/max in the retained ordered-bit semantics. Thus `min(max(unknown,+0),+1)` is provably finite and in [0,1] even when its unknown input contains NaNs; a single finite bound does not generally exclude the opposite NaN tail. Row min/max select source lanes and preserve their interval. Finite-domain ReLU maps negative values and negative zero to positive zero and preserves nonnegative finite values. No real-number NaN convention is substituted for these hardware operations.

A raw-FP8 reset contraction followed by BF16 readout, and the pure `virtual_mxu_matmul` equivalent, have a derived finite fact on the retained default 32x32 target. The custom E4M3 multiplier treats exponent-zero operands as zero; every other raw byte denotes a magnitude at most 480 in its integer field arithmetic, including the nominal NaN bytes. This is different from FP8 accumulator expansion, which flushes subnormals and NaNs to signed zero and has magnitude at most 448. A reset starts from +0 and has exactly 32 products. Each product is below 2^18; a conservative per-MAC bound `(B+2^18)*(129/128)` keeps all 32 BF16 accumulation steps below 2^25, far below overflow. The selected IPT path additionally sanitizes every output NaN/subnormal to zero and infinity to maximum finite. This proof describes the selected custom-FMA/IPT hardware, not arbitrary BF16 contractions or a different configurable PE architecture. Accumulation, even after a finite reset, stays unknown in this deliberately bounded analysis.

Finite input operands do not prove finite add, subtract, multiply, row sum, exp, reciprocal, or general accumulated contractions. In particular, BF16 arithmetic can overflow and reciprocal can receive zero. Softmax is not automatically assigned a unit interval: the LUT, input-domain and reciprocal obligations must be established separately. Unknown cases retain PACK. The contract is honored only as an assumption of the source program; the verifier checks its type, not runtime truth.

## Parameterized clamp rules and proof export

All rules require the verified dialect's 32x32 BF16 source, 32x32 E4M3 destination, scale byte 0..255, a single-block resource lifetime, and a free selected-unit accumulator. These fixed tile types are the supported shape parameters; this pass does not invent alternate tensor shapes or dtypes. The scale and engine are parameters, never graph-specific constants.

For codes 0..246, omit the lower clamp only when the derived source domain is nonnegative. Omit the upper clamp only when the derived source domain is the unit interval and the scale code is at least 119, for which the positive cap is at least one. Codes 247..255 omit both clamps by the converter equation proof. Strictly nonzero clamp bounds preserve the exact signed-zero and subnormal bits when a clamp is omitted. Constants are lazily materialized and shared per scale, so a later source needing additional bounds cannot borrow missing constants from an earlier unclamped source. Caller `finite_src` supplies only finiteness, never a range fact. The original BF16 source and other consumers stay unchanged.

`--lower-atlas-guarded-pack=annotate-facts` emits diagnostic attributes on each retained PACK or replacement BF16 accumulator load: `atlas.derived_finite`, `atlas.derived_nonnegative`, `atlas.derived_unit_interval`, `atlas.caller_contract`, `atlas.proof_reason`, and `atlas.pack_finite_proof`. The last is `derived`, `caller_finite_src`, or `unproved`; derived proofs take precedence when a caller promise is also present. These attributes report analysis output and are never trusted as analysis input. The default pass emits no diagnostic attributes.

Other established exact candidate identities remain guarded catalog entries, not enabled patterns: uniform-scale PACK/transpose commutation needs a BF16 transpose representation; contraction orientation reversal requires matching single-consumer orientation, same MXU0 K-order and +0 seed; row-max/positive-scale commutation requires its specifically proved constant and normal-product domain. This analysis tracks no normal/nonzero or row relational facts and does not claim those orientation/scale-max obligations are discharged. ReLU/max(+0) is proved on all 65,280 finite BF16 encodings, including subnormals and both zero signs; it remains disabled because the replacement adds work, there is no fused opcode, and no performance gain is demonstrated. Exp-to-exp2, reciprocal-to-division, arithmetic reassociation and generic accumulator-add fusion remain rejected by known counterexamples.
