# Extending exact rewriting

The shared mechanism belongs in Merlin's `semantic_compiler.egraph_terms` and `semantic_compiler.rewrite_selection` modules. Atlas virtual parsing, arithmetic facts, rule packs and resource-aware materialization belong at the Atlas provider boundary. This division was necessary because immutable values can share a generic e-graph, while Atlas state chains, accumulator slots, allocation and scheduling require its own compiler. The optional Python egglog implementation and the older Rust `egg` bridge are separate mechanisms; neither inherits the other's qualification.

Start with the [provider flow](egglog-selection.md), [encoding boundary](egglog-ir.md), [fact lattice](egglog-facts.md) and [exact rule library](egglog-rules.md). The current provider supports one straight-line argument-free virtual function. An unsupported region, mutable handle or unknown arithmetic fact must remain an explicit refusal or opaque anchor. Extending coverage requires a new round-trip gate, not merely another parser spelling.

## Add an Atlas family

1. State the equality in raw Atlas formats and identify the exact source arithmetic. Give an exhaustive domain argument where feasible, or a precise guard whose proof covers every admitted input. Record NaNs, infinities, both zero signs, wrapping exponents, rounding points and overflow behavior. An IEEE identity or sampled accuracy result cannot authorize an exact rule.
2. Add reusable transfer facts to `atlas_egglog_facts.py` only when the operation semantics justify them. Preserve unknown values conservatively and keep facts bound to the source and explicit caller-contract context. Export the required facts through `register_facts`; avoid a per-program rule or implicit contract. Authenticated table-backed transfer functions are one option for non-monotone raw arithmetic; their data and qualification records must participate in admission pins.
3. Add the guarded egglog law to `atlas_egglog_rules.py`, or a separate provider rule pack composed with it. Match the complete relevant operation/attribute/type vocabulary. Identical values may be shared, but distinct loads, state tokens and mutable resources do not become interchangeable. Include directed extraction tests and refusal cases that exercise the guard rather than restating the implementation.
4. Decode pure changes through `atlas_egglog_ir.py`. A family requiring stateful instructions needs a checked external recipe, as PACK uses in `atlas_egglog_pack.py`: reanalyze the decoded source, verify producer and scale identity, reconstruct the original state/resource boundary and refuse unavailable resources. Do not infer legality from the e-graph's equality alone. Reverify and physically compile every candidate.
5. Supply the operation's observed timing fact and resource demands to `atlas_egglog_cost.py`. Unresolved costs must be explicit. Pressure and reuse estimates are shortlist heuristics; the real allocator is authoritative. If materialization changes live ranges, preserve an exact baseline fallback, as the optional bounded splat-sharing provider does.
6. Qualify consumed outputs against an independent raw-byte oracle in the bit-exact model and retained RTL harness, with complete output addresses, DRAM/VMEM guards, repeated invocations and completion checks. Bind source, emitted program, fixtures, arithmetic data, compiler, runtime helpers and measurement authority to the receipts. Keep failed or unsupported cases visible.
7. Compare the same exact laws, guards, policies and measurement budgets against the directed hand control. Report source/binary aliases as ties, distinguish a shortlist from an exhaustive bounded pool, and separate model cycles from RTL cycles. A new rule can improve both strategies equally without demonstrating a search advantage.

The library deliberately excludes general contraction engine reassignment and reduction reassociation. MXU0 and MXU1 have different rounding architectures: finite products `[256, 1, -256]` produce zero on the systolic engine and one on the inner-product engine in independently checked model and RTL runs. An additional arithmetic-only counterexample uses nonnegative integer products `[256, 1, ..., 1]` (31 ones), which round to 256 versus 288 under those arithmetic policies; this example does not claim another hardware run. Finite, nonnegative or integer-valued facts alone are insufficient to establish general engine equivalence. PACK's engine alternatives rely on their separately qualified conversion equation.

## Add a target provider

Merlin's generic modules contain no target arithmetic, instruction encoding, latency table or parser. A provider supplies a typed source-to-immutable-value encoding, exact rule pack and analyses, a validated decoder/materializer, cost and resource metadata, and callbacks for compilation, independent oracle checking and qualified execution. The canonical target description determines the supported types and operations; missing semantics or execution authority remain blockers.

Use `Value.anchor`, `Value.apply` and ordered `Inputs` forests for the immutable surface, then bounded `saturate` and joint `extract`. Supply the marginal cost callback and a topological resource description for `estimate_dag`. Use `shortlist` to retain the native and required comparison controls. Pass admitted candidates and explicit target metric/tier declarations to `select_measured`; every winning candidate needs a complete qualified target grid bound to its actual program bytes. A provider declaration is an authenticated derivation record, not an independent theorem checker.

The K1 signed-i8 ReLU example in Merlin demonstrates this boundary using the canonical capability contract, all 256 encodings, guarded tail cases and executed scalar primitive counts. Its `host_functional_cost` tier does not establish K1 device timing or RVV throughput. Other targets need their own semantic, lowering and measurement authority before their rules can carry stronger claims.

The current Atlas workflow uses explicit `PYTHONPATH` selection of a compatible Merlin checkout and an existing egglog environment. The [selection guide](egglog-selection.md) gives generation and gate commands; [materialization comparison](egglog-materialization-comparison.md) documents optional equal-policy sharing. Pin the chosen modules and data before execution, preserve their source files for the lifetime of a campaign, and assemble subsequent changes in a separate worktree.
