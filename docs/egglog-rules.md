# Exact Atlas egglog rule families

`tools/atlas_egglog_rules.py` uses the encoder's actual `Value.apply(op, attrs_json, type, Inputs)` representation. Register the program's immutable roots, call `register_facts(graph, roots, program_facts=analyze_program(program), program=program)`, then run `EXACT_RULES.saturate()` and decode every extracted root. This prototype supplies candidates; source/effect validation, physical resource allocation and measured qualification remain separate checks. Attributes are canonical raw MLIR strings; rules match the declared operation attributes exactly, and proof annotations are never treated as premises.

The copy rule removes a BF16 VPU `mov`. RTL `VectorEngine.scala` selects the unchanged input vector for MOV, and the model's corresponding operation copies the raw register bits. Consequently every lane, including either zero and every NaN payload, is preserved.

The layout rule removes two consecutive FP8 XLU transposes. `XLU.scala` writes output element `(j,i)` from input `(i,j)` by indexing its full register buffer. Applying that coordinate permutation twice returns every one of the 1,024 positions to itself, for all 256 possible byte values at each position. It does not remove a single transpose, convert layouts across an operation, or move an effect.

Min/max idempotence and absorption are bit-exact over every raw BF16 input. `VectorParam.compareReturnMin/Max` transforms a negative encoding by bitwise complement and a nonnegative encoding by XOR with `0x8000`, then compares unsigned transformed encodings and selects an unchanged operand. This transform is bijective on all 65,536 codes, so the comparator defines a total order, including both zeros, infinities and all signed NaN payloads. The total-order lattice identities `min(x,x)=max(x,x)=x`, `min(x,max(x,y))=x` and `max(x,min(x,y))=x` hold universally in either displayed outer-operand order. No host IEEE NaN or zero behavior is assumed. Additional guarded rules remove a min/max operand only when source intervals prove `left.high <= right.low` (or the reverse), which proves that every possible pair selects the same operand.

ReLU elimination is guarded by finite raw nonnegative inputs, which excludes negative zero. The finite RTL table is exhaustively checked: a finite negative sign-bit input maps to positive zero and a finite nonnegative sign-bit input preserves its exact encoding. Its output is therefore a fixed point on that domain, proving finite-source `relu(relu(x))=relu(x)`. A mathematical nonnegative fact alone cannot eliminate ReLU because `relu(-0)=+0`. Unknown, infinity and NaN inputs do not qualify for these ReLU rules.

Fresh arithmetic qualification checks all raw splat encodings, the entire finite ReLU table, 1,048,576 directed raw min/max pairs, all UNPACK scale/input pairs and all transpose coordinates. The sampled pair count is evidence that the implementation matches its source equation; the bijective-total-order argument above proves the min/max families for every pair, rather than inferring universality from sampling. The consumed-output gate compiles native and actual egglog-extracted variants and compares independently predicted output bytes with fresh model and retained RTL execution, with two invocations and complete DRAM/VMEM guards. Scratch receipts record exact source/program/compiler/oracle hashes and any parked infrastructure failures; this document alone is not an execution receipt.

State and MXU resource handles have no egraph constructors. `combined_rules(*additional)` is the library hook for separately qualified PACK rules. There are no general engine swaps, arithmetic reassociations, add/multiply identities or conversion round trips. `bounded_constant_sharing` only proposes splat materialization groups under an explicit maximum live-span and concurrent shared-constant budget; it counts BF16 constant tiles, not an allocator's complete physical register pressure, and is not enabled automatically. The decoder keeps existing source sharing and limits new subexpression sharing to a root, with optional dead-pure pruning after extraction.

The fact exporter requires the exact current Program when seeded by ProgramFacts, verifies its SHA-256 and explicit contract context, and exports only nodes reachable from the supplied roots. A stale local SSA name cannot transfer a proof between programs. Tests include both rejection paths and an explicit opted-in contract success case.
