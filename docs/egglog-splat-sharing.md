# Optional BF16 splat materialization sharing

`tools/atlas_egglog_sharing.py` offers a separate materialization choice after egglog extraction. `bounded_splat_sharing(source)` returns the original source bytes without parsing or invoking a compiler. It is not connected to the exploration driver, and existing per-use rematerialization stays the default.

Enable it explicitly with `bounded_splat_sharing(source, enabled=True, atlas_opt=compiler_path, expected_compiler_sha256=compiler_hash, max_distance=16, max_constants=2)`. The result has `source` and a JSON-serializable `evidence` dictionary containing source/compiler hashes, removed/retained SSA names, exact attributes/types, distance decisions, evictions and actual allocation reports. Callers should retain that evidence with any candidate receipt.

The `shares` list records proposed aliases. They actually occur only when `selected` is `shared` and `status` is `accepted`; every other status selects the baseline and applies zero aliases. The effective policy is therefore the requested `d<max_distance>-c<max_constants>` only for `selected=shared`, and `none` otherwise. Bind the selected source to `candidate_sha256` for sharing or `baseline_sha256` for fallback. A refusal can legitimately report many proposed aliases while returning the baseline unchanged; do not count those as realized savings.

Only `atlas.virtual_vpu_splat` definitions with the exact same BF16 raw bits, result type and every attribute are eligible. Signed zeros remain distinct, different NaN payloads remain distinct, and metadata differences prevent sharing. This is equality of an immutable pure term, not an arithmetic identity or a new finiteness premise. No caller contract is added or inferred. Only already-dominating definitions in the bridge's single straight-line region are reused. Unsupported input returns the unchanged source with `status=unsupported` and supplies no allocation qualification.

`max_distance` bounds original operation ordinals from the retained definition to the final use of each removed definition, including uses after its original definition. It does not merely bound the gap between definitions or between successive reuses. `max_constants` bounds the distinct structural keys kept eligible for reuse, evicting the oldest retained key when full. Existing live ranges remain unchanged; neither heuristic guarantees total pressure or allocation. A large window can reconstruct the many-scales pressure failure that per-use rematerialization repaired.

The enabled path invokes the requested compiler with `--verify-atlas-virtual-stream --lower-atlas-virtual-to-machine=allocation-report=...` on the baseline and proposed shared source. It selects sharing only if both sources pass lowering and the actual allocation report says they fit. A refused candidate returns the exact baseline with `status=allocation_refused`; a refused baseline returns it unqualified with `status=baseline_refused`. No speculative machine stream is used as a substitute for source compilation. Later transformations, including scheduling, require their own final compilation and allocation checks before measurement or selection.

Only the parsed operation operand-list span is changed. Attribute strings, metadata containing SSA spellings, comments, state/resource definitions and effect order are preserved. The reconstructed source is parsed again before compiler qualification. Successful allocation proves representability for that pipeline; independent consumed-output and guard checks are still required before claiming execution correctness or a target benefit.

Directed compiler tests in `test/test_atlas_egglog_sharing.py` cover raw bits, metadata, dominance, unsupported regions, bounds, default identity, compiler pins and a real mixed-bank refusal: baseline peak15 versus candidate peak16. Run them with `PYTHONPATH=tools ATLAS_OPT=/absolute/path/to/atlas-opt python -m unittest discover -s test -p test_atlas_egglog_sharing.py -v`. Without `ATLAS_OPT`, compiler-dependent tests skip explicitly.
