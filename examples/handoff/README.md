# Atlas handoff examples

This directory keeps the **source programs** for four bounded examples. Build
products go under `out/`; they are regenerated by the commands below.

| Example | Checked-in source | Generated path |
| --- | --- | --- |
| Physical MLP tile | [Atlas machine MLIR](mlp_tile/01-atlas-machine.mlir) | `out/handoff/handoff_mlp_tile.*` |
| Physical attention tile | [Atlas machine MLIR](attention_tile/01-atlas-machine.mlir) | `out/handoff/handoff_attention_tile.*` |
| Virtual two-layer MLP | [Atlas SSA MLIR](virtual_mlp/00-atlas-virtual-ssa.mlir) | `out/handoff/virtual_fp8_two_layer_mlp.*` |
| Captured MLP structure | [Linalg MLIR](captured_mlp/00-linalg.mlir) | `out/captured-mlp/compiler/*` |

The executable test inputs are under `test/examples/`. The physical MLP and
attention programs are hand-authored fixed 32×32 instruction streams. The
virtual MLP demonstrates SSA values before physical allocation. The captured
MLP is a sanitized Linalg example with separately frozen test weights and an
explicit diagnostic FP8/BF16 policy. These are narrow examples, not complete
model or SoC programs.

## Generate Atlas, LLVM, assembly, and ELF stages

Build the OOT tools first using the pinned MLIR/LLVM installation described in
the [root README](../../README.md). Then run from the repository root:

```sh
python tools/export_llvm_handoff.py \
  --atlas-bin-dir build/bin \
  --llvm-bin-dir /path/to/llvm-install/bin \
  --linker /path/to/ld.lld \
  --output-dir out/handoff
```

Use a new empty output directory for each run. For each of the first three
examples, the exporter writes `.atlas.mlir`, `.llvm-structured.mlir`,
`.llvm.mlir`, `.ll`, `.s`, `.o`, `.elf`, `.disasm.txt`, `.word-map.json`,
`.physical-program.json`, and a manifest with source and tool identities. The
virtual example also writes `.virtual.mlir`. The structured LLVM stage retains
one typed call marker per Atlas instruction; the final LLVM stage contains an
encoded inline-assembly block. The word map ties each instruction to its
source operation. The exporter checks the emitted words against the object and
linked ELF text.

```sh
/path/to/llvm-install/bin/llvm-readelf -h out/handoff/handoff_mlp_tile.elf
/path/to/llvm-install/bin/llvm-objdump -d out/handoff/handoff_mlp_tile.elf
```

The [captured MLP instructions](../../docs/captured-mlp-compiler.md) show how
to generate its additional Linalg, virtual, physical, constant, and ELF
stages from the checked-in source fixture. Generated constants, objects, ELFs,
maps, manifests, and disassemblies are kept out of Git.

These ELFs expose selected Atlas instruction words for inspection. The selected
core needs its separate preload and start protocol; the ELF is not a host ABI
or an integrated SoC launch artifact. The tests regenerate stages and, when
the selected standalone core is supplied, execute the linked instruction text.
