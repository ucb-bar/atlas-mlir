# Chip runner

Owned runner and checker for `atlascc run OUT`. Deployment stages these same modules in `OUT/kit/bench` and authenticates them in the kit inventory. Run refuses if the installed and staged tools differ. Repackage after updating tools.

```
atlascc run OUT --dry-run [--inputs FILE ... [--reference DIR ...]]
atlascc run OUT --simulate [--inputs FILE ... [--reference DIR ...]]
atlascc run OUT [--negative] [--serial PATH]
atlascc run OUT --inputs FILE ... [--reference DIR ...] [--serial PATH]
atlascc run OUT --inputs - [--serial PATH]   # one "INPUTS [REFERENCE]" line per step on stdin
atlascc reference OUT --inputs FILE -o DIR
```

Without `--dry-run` or `--simulate`, `atlascc run OUT` is a live run on the chip. Each command runs authenticated preflight and exactly one rung: the positive, or with `--negative` the expected numerical failure rung. The next rung needs a separate decision and command. There are no automatic retries. With `--inputs`, the positive rung is followed by resident steps (see Steps), which have not run on silicon. The kit's `run.sh` wrapper is the bench path: it passes `run_kit.py --allow-transport` for its one attempt, takes OpenOCD from `NOV_OPENOCD`, and stops the runner as a transport error if it outlives the sum of the runner's own waits. `atlascc run` applies the same bound and also stops on SIGTERM or SIGINT; each stop is a transport error (`rc=2`) after the runner's own cleanup stops OpenOCD, and the terminal capture (stdout and stderr) always ends with `rc=`. The checker requires completion and every predicted output byte. Transport errors never qualify a negative; a negative that fails exactly as predicted prints `RUN PASS (negative rejected as expected)`. Logs use a fresh `OUT/run-*` directory. `--serial PATH` selects the board's UART device; the default is the Linux path `/dev/serial/by-id/usb-FTDI_Dual_RS232-HS-if01-port0`.

Simulation requires an inventoried composed plan and the simulator tools on PATH or selected by environment. It executes compiler programs and host ELFs. Simulation is not hardware qualification. Its negative executes a changed input and requires a numerical boundary mismatch; an arbitrary exception fails. `run_kit.py BUNDLE --composed --recheck --logs LOGS` rechecks a finished positive run without a transport: from the saved outputs and journal alone, it rebuilds every value and compares every boundary and value reference byte for byte, listing all-zero references without counting them.

Live preflight accepts only an OpenOCD build declared in [openocd-builds.json](openocd-builds.json): the executable's sha256 and its exact `--version` banner line. The checker requires a declared banner line in the recorded `openocd.log`. Adding a build is one row in that file (a lowercase hex sha256 and a banner beginning `Open On-Chip Debugger `, both unique, or the table refuses); kits stage it with the other tools, so redeploy to use it. On macOS the process check runs `pgrep -afl` and the UART check `lsof -t` on both names of the port (`/dev/cu.*` and `/dev/tty.*`), and paths may pass through the system links `/tmp`, `/var`, and `/etc`; Linux keeps `pgrep -fa`, `fuser`, and no exceptions. A missing check tool refuses by name (on Linux, `pgrep` comes from procps and `fuser` from psmisc). On one Mac these checks ran by hand, in a dry connect, and in one live positive and negative pair each for the K32 and K64 kits.

Kits declare `runner.record_tag`, the prefix of the UART `STATUS`, `HASH`, and `COMPLETE` records. The linker harness and packaging take it from one constant.

## Staged plans

A staged plan declares `composed.values`, the whole tensors the bench host holds. A region input may read `{"value": ID, "range": R}`, a weight file may carry `range`, and an output binds back with `value: {"id": ID, "range": R}`; a range is `count` runs of `bytes` at `offset + i*stride`, and an omitted range is the whole value. Every byte is written once, read only after it is written, and compared with the same bytes of the value's reference when written. A step region declares its page-aligned `window`, its step `deployment`, the device `images` it launches (`program` and `plan`), and its `launches`. An `elf` step is a linked platform ELF: in simulation it runs unchanged in Spike with the Atlas devices of `spike_atlas.cc` (IMEM and CSR words go to the model checker's functional runtime in `atlas_mlir/exactness`, VMEM is shared, and the UART records end the step and must hash every declared range), which needs Spike, dtc, and g++. An `application` step, used only where no ELF links, runs its generated driver natively over the same runtime. `composed.negative` names one value and a packaged replacement for its initial bytes; qualification runs it as the negative, which must fail only numerically.

Live, `atlascc run OUT [--negative]` runs a plan whose every region is an `elf` step, one rung per command: the plan, or its declared negative, which must fail only numerically. Other composed plans refuse live execution. One OpenOCD session serves every step. Each step's ELF (host code and window image) is loaded and verified, its inputs are written, and the core resumes at the entry. The load leaves out the window spans the ELF's harness clears before it binds Atlas (its `atlas_window_zero` table, recorded as `window_zero` in the step's `link.json`) and the inputs, weights, and outputs, which the runner writes in full next (the output poison too, read back byte for byte), so the memory at the start is what the full image and those writes give. No loader verifies the cleared spans, so the harness reads every cleared byte back and, if one is nonzero, reports `STATUS -100` without binding Atlas, which fails the step. The table is interim: the generic form is a sparse ELF whose zero spans are NOBITS, so every loader (this one, the single-kit loader, and a one-ELF DRAM image, which gains nothing from the table) skips them unchanged. The UART must report status 0, one hash per declared range, and completion. Every hash range is dumped and must equal its hash before the runner judges the outputs and feeds them to the next step. Every step output must be a hash range. The plan declares `receiver_baud`. OpenOCD and the UART follow the single-kit rule: `NOV_OPENOCD` with a declared build's digest and banner, no other bench process, and a free UART. The rung stops like a single-kit rung, at a wall-clock bound above the sum of its steps' own waits or on SIGTERM or SIGINT, as a transport error (`rc=2`) after cleanup; cleanup runs every step (Tcl close, OpenOCD stop, UART and log close) even if an earlier one fails, any cleanup failure is a transport error even after the negative's expected mismatch, and `OUT/run-*/positive-terminal.txt` (or `negative-terminal.txt`) ends with the KIT line and `rc=`. This path is tested with in-memory peers and with an OpenOCD peer that runs each loaded ELF in Spike, not on silicon.

## Board DDR kits

A plain `atlascc deploy` (no `--jtag`) declares `transport: spi` in `deploy-status.json`, and `atlascc run OUT` chooses the link from that declaration, with no flag; any other declared transport, or none, refuses unless it is `jtag`. `ddr.py` holds the protocol and the `Transport` interface (identify, write, read, start, records, close, plus the board's `journal` path and `requires_tohost`); a link implements only those. The protocol checks the kit inventory, the ELF's loads against `loader-manifest.json`, and the board's DDR against `memory-plan.json`. On a link whose hart caches DDR (`requires_tohost`, every real board: Shuttle's write-back L1 has no flush, and only the tohost exit code evicts the outputs), an ELF that links no `tohost` is refused before any write. It writes every chunk and zero-fill tail, reads each back, and stops at the first whose SHA-256 differs, before the hart starts; starts the hart at the entry; and requires status 0, one hash per hash range, and completion on the UART, the exit word 1 at `tohost` when the ELF links one (another odd word is the program's nonzero status), DDR bytes equal to each reported hash, and bytes equal to `reference/output_NNN.bin`. The board's one load journal (`Transport.journal`, shared by every deployment run on that board) records the chunks verified on one board session (`identify()` names it), keyed by destination, length, and hash: an interrupted load resumes from the first unverified chunk, any write over a chunk's range forgets it, a run forgets every writable chunk, and the read-only weights stay loaded for the next ELF. Read-only segments are trusted, not enforced, across runs: nothing on the chip stops a program writing one, and a program that does fails its next run as a mismatch. A link that cannot name its session gets each journaled chunk read back before it is trusted.

`atlascc run OUT --simulate` runs `chip.elf` and then `negative/chip.elf`, which must produce its packaged evidence and differ from the reference, on `ddr_sim.py`'s simulated board: DDR is a sparse file in `OUT/simulated-board`, filled with 0xA5 up to the end of the device window's used span at power-on and written directly as FireSim's loadmem writes DRAM, and the hart is Spike with that file as DDR and the Atlas devices of `spike_atlas.cc` over the pinned model, as for step ELFs (Spike, dtc, g++, and `COMPOSED_MODEL_PYTHON`). The board's DDR persists across runs. `--dry-run` checks the kit and both ELFs' load plans without a link. `atlascc run OUT` refuses until the board's SPI loader exists; `--negative`, `--serial`, `--inputs`, and `--reference` are not supported for these kits yet. This path is tested with a scripted in-memory board and on the simulated board, not on a board. Each run records `link: simulated` in `run-*/NAME/run.json` and prints its verdicts with `(simulated board)`. One run at a time holds the board (`OUT/simulated-board/lock`), and SIGTERM or SIGINT stops the run and kills the simulator's whole process group. The simulated board does not model the SPI link, serial-TL and its clock, caches and coherence, reset through the boot address register or MSIP, or timing; it is exempt from `requires_tohost` because Spike has no cache. The runner hands the transport the kit's budget in chip cycles (`platform_assumptions.timeout_cycles`, 12,000,000,000 today; for a kit packaged before that field, its `timeout_seconds` at its `bench_facts.core_clock_hz`), which a board transport converts at the clock it measures. On the simulated board, 4 CPU seconds per 100,000,000 budget cycles (480 s) bound the simulator's CPU seconds (its whole process group) at any kit clock, not wall time, so a loaded host cannot fail a run; the allowance is there because one DroNet 200 run used 108.4 and 119.8 CPU seconds (positive and negative), leaving no margin at 120. A simulator that blocks without using CPU stops at 10 times that limit in wall time. A kit whose simulation needs more CPU than the timeout fails closed but falsely. Real transports keep the wall-clock timeout.

## Steps

Each `--inputs FILE` is one step: an `.npz` holding `input_000`, `input_001`, and so on, one per `deployment.inputs` row by `index`. Shapes, dtypes, and byte lengths must match the row exactly; i8, u8, i32, i64, f32, and bool use their numpy dtypes, and BF16 uses uint16 storage bits. Any other member, a missing one, or any other file refuses. Listed files and references are all validated before any transport opens. With `--inputs -`, `atlascc run` reads one `INPUTS [REFERENCE]` line per step from stdin, validates it, runs it, and prints its result line before reading the next, so a simulator loop can send an observation and wait for the action; one invocation qualifies once and keeps one resident session for every line.

Each step prints `STEP NNN EXACT (...)` or `STEP NNN UNCHECKED (no independent reference)` with its `outputs=OUT/run-*/step-NNN/outputs.npz` (`output_NNN` arrays typed by `deployment.outputs`, beside the raw `output-<n>.bin` dumps); the verdict line counts unchecked steps. A step is checked against the packaged reference when its inputs equal the packaged ones. New inputs have no precomputed reference: such a step is unchecked unless `--reference DIR` (one per `--inputs` file, or the second field of its stdin line) supplies an independent one, and then every output byte must equal it or the run fails. A supplied reference must be what `atlascc reference OUT --inputs FILE -o DIR` writes on the compile host: the source evaluator run on those inputs, with the deployment's authenticated capture, placement decisions, target rules (npu_model b97b2f5, numerics="rtl"), and evaluator, exactly as deploy made the packaged reference. `atlascc run` refuses a reference whose record differs from the kit's packaged one in anything but its inputs and outputs, whose input digests differ from the step's, or whose archive differs from its record. `atlascc reference` also refuses unless the deployment's packaged inputs are the capture's user inputs in order, since `input_NNN` names the source's user input NNN there.

The first step opens one resident session: the window and ELF (or the composed host code and weights) are loaded once. A reference call with the packaged inputs must reproduce the frozen outputs, at open and again at close. Each step restores mutable allocations from the packaged window, poisons the outputs, writes the new inputs to their fixed ranges, restarts, and dumps every output. In a live composed run, every data write the runner makes (the output poison, inputs, and any weights) is read back and compared byte for byte, and that readback is also the poison check; ELF loads are checked with `verify_image`, which compares a CRC-32. Immutable parameters and code stay resident. A composed host ELF stays resident only if none of its segments overlaps another plan range or a step application's window, which that application clears, and weights likewise; anything else is rewritten before its region on every call. A region whose output reads short or stays poisoned is a runtime failure, never the numerical mismatch that qualifies the negative. Every step re-verifies the bundle against the inventory digest pinned at start. From the first step until the session has closed, SIGTERM or SIGINT stops it wherever it is, in a call or waiting for the next stdin line: the close halts the hart and stops OpenOCD within its own bounded waits, and the run fails. The terminal record `session-terminal.txt` in the run directory lists each step's result line and ends with `SESSION PASS`, `SESSION FAIL ...`, or `SESSION TRANSPORT_ERROR ...` and `rc=` (`rc=2` on any stop). Each call is bounded by the runner's UART and RPC waits; waiting for stdin is not. Live outputs must also match the device's own UART hashes and differ from the poison pattern. Composed plans name each deployment output's producing region in `source`. Live steps are tested with in-memory peers and with an OpenOCD peer that runs the loaded ELF in Spike, not on silicon.

The same steps are a Python session:

```python
from atlas_mlir.deployment_run import Run
with Run(OUT) as run:                                     # Run(OUT, simulate=True) for a composed plan offline
    logs, outputs, checked = run.step(INPUTS, REFERENCE)  # outputs: bytes per deployment.outputs row; checked is None if unchecked
```

The bench negative can reuse the positive ELF with an authenticated input-byte patch from the pre-link mutation receipt. The runner verifies the loaded input preimage and applies the patch after ELF loading. Missing predictions refuse.

Run the owned suite with `python -m unittest discover -s test -p 'test_chiprunner*.py'`. The deployment and front-door tests are collected under the same test directory.
