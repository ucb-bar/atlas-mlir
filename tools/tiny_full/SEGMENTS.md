# Native Tiny boundary preparation

`capture_boundaries.py` runs the production C orchestration with checksum-bound arithmetic projection replies. It requires the complete 128-token prefill and two greedy decode steps and its original exact C replay gate. It constructs no device Core and produces no numerical instruction-execution receipt.

The shared C API has begin, layer, and finish operations. Begin validates actual tokens and embeds them; layer executes exactly the requested next layer through the unchanged block implementation; finish performs final norm, the full LM head, argmax, and committed-state publication. A failed arithmetic operation poisons the continuation. `tiny_full_model_step` composes these same operations, preserving the default full-host flow. `tiny_full_get_live_layout` returns a versioned 64-byte ABI descriptor with compiled workspace/hidden offsets and allocation extents; continuation state is 32 bytes without pointers.

Run the producer with `--capture PATH --capture-sha256 HASH --gate PATH --gate-sha256 HASH --merlin COMPARISONS_DIR --cc PHYSICAL_CC --out FRESH_DIR`. It first checks the full-step path against all 465 original actual projection predecessors/replies and all 132 KV arrays, three last-row logits, and actual greedy feedback. It repeats the checks through 69 layer/head phases, clearing dead workspace scratch before each phase. The two ledgers must be identical before preparation passes.

Successful output has 70 ordered reference boundaries and 145 fixed regions: four KV banks, two hidden buffers, continuation/control, and all 137 output-history buffers. Regions have content-addressed payloads; unchanged values share storage. Source snapshots, compiler dependency pins, both original receipts, the compiled native library, and every boundary payload are covered by `SHA256SUMS`. `native-gate.json` is a captured-reply C gate compatible with the existing full-host builder, and explicitly has fresh instruction execution false. `receipt.json` has status `PREPARED_REFERENCE_BOUNDARIES_NOT_EXECUTED`; `boundaries.json` has `REFERENCE_BOUNDARIES_ONLY` and `elf_bound=false`.

These semantic snapshots have no physical ELF addresses. The segment builder and `tiny_segment_contract.py` derive the writable live inventory from the segment-capable RV64 ELF, bind its actual entry and stop code, and map the compiled layout to that image. Each segment starts a fresh stack and executes real layers, with its global invocation sequence and launch range admitted before constructing a fresh device. Every numerical link requires actual guest boundary comparisons and exact, drained kernel receipts; native preparation alone cannot qualify the chain.

The optional full-host builder profile is selected with `--segment-boundaries PREPARED_DIR --segment-sha256 SHA256SUMS_HASH --segment-model-root PINNED_MODEL`. It uses the shared default transport and a common layer/head dispatcher, exports stable KV/workspace/continuation symbols, and binds C1 `segments.json` to the one ELF and full Tiny contract. Normal builds keep their existing target and flow. The segment contract reassembles all distinct selected programs, audits read-only pointers and writable allocations, validates the entire native chain, and requires the actual 9e/curve profile before constructing a device.

`tools/host_iss/run_tiny_segment.py --bundle-root BUNDLE --model-root MODEL --qemu QEMU --segment-index INDEX --wall-seconds CAP --out FRESH_DIR` starts a fresh guest and stack, restores every admitted semantic byte, seeds the global invocation sequence, and executes one real layer or head. The local index is `23*step+layer`, where layer 22 denotes the LM head. It compares all 145 next-boundary regions, actual host pointers/cursors/mailbox/drain state, ordered global kernel identities, exact DMA, and functional UART completion. `--corrupt-region hidden_0|hidden_1 --corrupt-offset BYTE` changes one restored actual guest byte after admission for an explicit negative execution control. Outputs include current stage/actual completed counts in `run-state.json` and per-process peak RSS in the final receipt.

The default builder target remains the standalone full greedy-inference host. The optional segment target requires captured entry state and a harness request; its ELF must be reported separately. Full and segmented native paths use the same C arithmetic and orchestration functions, with exact predecessor, KV, logits, and greedy-feedback checks.
